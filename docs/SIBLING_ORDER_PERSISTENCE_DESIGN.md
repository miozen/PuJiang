# P2-3 同胞显示顺序持久化方案

状态：**第一步隔离存储与复核已实施；工作台接入和复杂关系未实施**。本方案服务于 [D-026](DECISIONS.md#d-026--专业族谱编修工作台与显式草稿)、[D-028](DECISIONS.md#d-028--真实谱系只读横向投影的处理原则)；进度与本机状态以 [计划](CURRENT_PLAN.md) 和 [接力](HANDOFF.md) 为准。D-014 的生产恢复、自动合并和按谱候选切换关闭条件不变。

## 2026-11-06 新规则对本方案的影响（待实施）

用户已确认新增配偶排在既有配偶之后；子女和兄妹按男女分组、同性别新增者追加，手动排序不能跨性别组，支持左键拖动；顺序按图表保存并重开保留。普通新增子女的默认另一位生父母改为当前图表显示的第一位明确夫妻配偶。现有未知性别人物须先更正才能参与排序，不猜测；用户不要求推断旧数据的录入先后。上述明确新增规则取代下文“新增同胞后一律不得自动追加”的旧规定，不取消其他关系变化、缺页及并发失效保护。

实现前须将当前窗口的图表身份与图表修订纳入读取和草稿：排序项以稳定人物、婚配或关系 ID 标识，不能用姓名或随机 ID 充当先后；新增人物、关系和当前图表排序追加必须在同一事务中提交或回滚。拖动只产生可保存的排序草稿，组成员不完整、性别未知、关系歧义或视图失效时拒绝应用；切图表、切谱和关闭须协调人物及排序草稿。新建子女时在同一版本读取完整婚配候选及当前图表排序，保存时重新校验数据代数和图表修订，不能只由 UI 传入未经核实的配偶。不同图表的配置互不覆盖；非当前图表因关系变化产生的失效仍需复核，不得静默改写。

原有 `SiblingOrderStorageSession` 仅支持唯一父母完整子女组，不支持配偶、无父母兄妹、增量追加或窗口图表选择；不能直接将其当作完整实现。迁移、图表存取、关系新增事务、投影、鼠标捕获与取消、草稿生命周期及失败提示均须联合验证；下方旧方案的具体默认行为仅作历史背景，冲突处以上述新规则为准。

本轮增量：`SiblingOrderStorageSession` 新增已确认图表主线的双亲组捕获和男女分组保存；独立配偶排序迁移和 `SpouseOrderStorageService` 支持保存、复核、图表版本竞争与回滚；按图表新增配偶命令已将人物、婚配和配偶排序追加放入同一事务，图表默认配偶命令尚未接 UI。上述内容仍不能处理无父母兄妹、图表切换、拖动或新增子女/兄妹及排序的同事务追加，也不代表完整 P2 或生产恢复验收。

## 目标与边界

- 用户明确：同胞**显示顺序按图表分别保存**；新增或删除同胞、父母关系变化时保留旧顺序供复核，复核前不自动套用。原始 `RecordedBirthOrder`、世代和人物关系始终保留，不把显示顺序当成谱载排行或出生先后。
- 首个实现切片复用当前已验收的两类完整分组：一个明确父母的完整子女组；无已知父母、以明确兄妹关系相连且同代的完整组。后者仅是用户指定的显示组，不推断共同父母或生物关系。多父母未选主线、跨页、缺世代、关系冲突、组拆分或合并等保持待处理，不创造推断。
- 默认仍是当前会话临时顺序；用户选择同谱图表并明确保存后才持久化，切谱、关闭、退出须协调未保存的排序草稿。不同图表可保存不同顺序；没有选图表时不自动新建或覆盖默认图表。
- 包含多组顺序的图表可增量编辑，但保存只针对用户明确选择的组；不得删除其他组、既有父母选线或未复核记录。本方案不实现持久排序、迁移、生产恢复或新格式交换。

## 已核实的现状与约束

1. `WorkbenchProfileWindow` 当前以稳定人物/关系 ID、谱载世代及排行原文构造会话分组，完全指定后绘制父子线；数据变化导致只读会话失效，清空排序。当前工作台没有图表选择/排序保存入口。
2. `LineageChart` 已保存族谱 ID、名称、`Revision` 和 `Generation`，`LineageChartChoice` 保留父母选线的历史人物与关系 ID；历史 ID 有意不设置到人物和关系的级联外键。现有 `LineageChartService.SaveAsync` 会替换该图表的**全部父母选线**，不能直接当作只保存顺序的命令。
3. `UnlinkGenerationV1` 覆盖 People、PersonRelationships、FamilyUnions 的写入，不覆盖图表表、谱系及房支；其 SQL 和既有触发器定义是不可改写的迁移契约。图表 `Revision` 是另一条并发边界。只读连接的版本/生命周期与单个版本数字不同，不能仅靠全库代数或仅靠图表修订判断安全。
4. 当前数据库备份是数据库快照，包含库内图表；v1 内部族谱交换模型不含图表及排序。数据库迁移及备份预检严格检查结构，新增表需要明确迁移和预检兼容；不能宣称 v1 交换包含新顺序，也不能静默把它转成人物谱载。

## 保存模型（推荐方案）

- 在同谱图表下增加独立的排序组及排序项，组有稳定 ID、组类型、独立来源快照版本与有序项；项保存人物 ID、明确位置、当时名称/谱载世代/谱载排行原文等复核展示信息。关系证据单独保存：唯一父母组的父母 ID、每条子女关系 ID/类型/双方；无父母明确兄妹组的全部关联 ID/双方和无父母证据。组内人物与顺序要求完整、位置连续唯一，图表与族谱必须匹配。
- 人物/关系 ID 是历史证据，不对它们设置删除级联；删除人物或关系后旧记录仍可展示并复核。排序项可随**用户明确删除图表**一起删除。名称是显示快照，不用于身份匹配、去重或自动修复；不得按相同姓名重连。
- 组身份和证据快照分离：稳定组 ID 标识此前配置；当前按同一读版本完整计算组，再比较所有成员、关系 ID/双方/类型、相关世代及谱载排行原文。新增、删除、换父母、关系类型变化、拆分/合并、缺页或冲突均列出具体差异，**不可自动应用**；不能由当前画布前 100 人的部分结果证明组完整。普通改名不自动改关系，但应展示当前与历史名称。
- 排序组保留自己的证据及其采集版本；**只保存排序时不得刷新 `LineageChart.Generation`，以免把旧父母选线错误标成已复核**。相反，既有选线的保存也不得覆盖或使旧排序被视为新验证。图表共享 `Revision` 用作任一图表配置写入的并发令牌；历史选线和排序各自独立校验与复核。需调整现有图表保存服务以保留排序及维护共同修订，不能仅新增写入口。
- 图表成员、关系证据和保留策略的表结构、外键、索引及迁移编号由实现时按 EF 和 SQLite 现有约定确定；新增表不是生产恢复功能。旧图表在迁移后没有排序记录，应显示“未设置”，不从姓名、ID、旧布局或现有谱载文字推断。

## 命令、草稿、并发和复核

1. **选择与暂存：** 在工作台明确选择/新建图表，展示当前组与历史排序。沿用右键上移、下移及右侧指定位置；完整顺序形成独立排序草稿。切人可保留同图表排序草稿；切图表、切谱、关窗、退出协调排序和人物草稿，分别提供保存、放弃、取消，失败保留相应草稿。切换图表不会隐式提交另一张图表。
2. **事务保存：** 统一排序命令以族谱 ID、图表 ID、预期图表修订、只读会话身份及预期受保护代数为输入，在同一事务验证图表所属、所有人物/关系/组完整、位置唯一与完整、组证据未变化，原子条件更新图表修订并写入所选组；只影响用户选择的组。版本比较须落在原子条件更新/写入中并核对影响行数，不能只做先读后无条件写。冲突、取消、数据库错误或任一步失败全部回滚，保留草稿及旧记录；并发保存两窗口不得互相覆盖。
3. **读取与有效性：** 使用同谱、同只读会话获取图表、修订、排序组及关系证据；分页必须证明组已完整读完，前 100 人不构成完整证明。应用前复核会话身份、数据版本、图表修订和请求身份；旧请求、旧图表或取消结果不得回填。任一依赖变化、证据不完整或无法证明不变时失败关闭。
4. **需要复核：** 展示旧排序、历史与当前成员及关系变化，不将旧顺序当作当前排行。用户可明确重排、放弃或取消；只有完整当前组经用户确认后，才能以新证据生成待保存草稿，事务成功后替换该组。不得自动把新人追加、删除旧项、覆盖其他组或以名字推定身份；并发期间再次变化须重新复核。
5. **提交后刷新：** 保存成功即为已提交；重开只读会话并重新核验图表/证据后恢复画布位置。若刷新失败，准确提示“已保存，但刷新失败”，不重复写入、不把已提交操作恢复为未保存；陈旧画布失效，其他人物草稿保留。

## 分步实施与验收

- **第一步：隔离数据与存储。** 建议先做单图表、单个完整唯一父母子女组的表迁移、版本条件命令、独立只读/复核服务及测试；暂不接工作台 UI。迁移前后在独立 SQLite 上核对旧图表无排序、旧选线保留、图表与谱隔离、备份包创建/预检，以及 v1 交换不含图表的明确边界。
- **第二步：安全接入工作台。** 选择图表、排序草稿、保存及退出协调；保存后刷新失败的提示与旧结果拒绝；在独立测试数据目录由用户验收逐人设置、上下移动、切图表/切谱、保存、取消、关闭和重开。完成该步前不宣称业务入口已完成。
- **第三步：明确兄妹组与复杂情况。** 单独接入无父母的明确兄妹组，验证新增/删除关系、拆分/合并和复核；多父母、过继及跨页扩展另行设计，不把简单组方案外推。用户此前要求小功能切片，不一次实现所有复杂关系。
- **隔离与失败矩阵：** 两谱/两图表独立、保留其他组选线和历史；并发同修订只能一方成功；同胞新增/删除、关系方向或类型改变、人物/父母删除、原文与世代变化、组拆分/合并、ABA 和跨页均不能自动套用；伪造 ID/跨谱拒绝；注入各写入点失败完全回滚；复核期间变更拒绝；保存后刷新失败准确报告；旧版数据库迁移、数据库备份预检与 v1 交换边界逐项检验。自动化之后使用独立虚构库进行实际窗口验收。
- **完成标准：** 各步骤分别完成规定本地 Release 构建、日常测试和适用 UI 测试；人工验收明确记录具体范围。性能、全部 P2 和生产恢复不由此推断通过；本地完成后不等待远端 CI。
