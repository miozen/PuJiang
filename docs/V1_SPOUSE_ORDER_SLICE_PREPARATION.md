# V1.0 配偶排序切片准备

> 状态：用户已批准 D-031 隔离实施；本文保留实施前的建议与验收条件，实际进度、验证结果和未完成项以[接力](HANDOFF.md)为准。业务决策以 [D-031](DECISIONS.md#d-031--v10-配偶排序与谱系上下文) 的 V1 领域层级更正为准。

## 层级与已确认规则

- Genealogy 是独立修谱项目，包含谱文（Document，文字资料概念）及多个相互独立的 Lineage。谱文具体实体、存储格式及人物传记关联尚未确定，不在本切片自行设计。
- Lineage 是人物身份、关系、婚配、世系位置、排行及配偶排序的业务隔离单位；不同 Lineage 即使位于同一 Genealogy，也不自动共享身份或同步修改。
- 每个 Lineage 对应一个逻辑编修画布。横向世系图、传统吊线图是两种 ViewMode，共享人物、关系、位置、排行、配偶排序和编辑命令；布局、缩放、视口等显示状态可独立。
- 配偶排序只属于当前 Lineage，不按 ViewMode 分别保存；新增配偶仅追加当前 Lineage 的该人物配偶列表末尾，排序调整仅影响当前 Lineage。新增子女采用当前 Lineage 排序第一位的有效夫妻配偶作为默认生母。
- 排序不改变婚配事实、人物身份或已保存的生母关系；D-030 首配偶限定补录、主动清空保护和生母候选范围继续有效。排序与婚配事实分离保存、拖动完成后自动保存、异常原始数据保留及修复入口、事务回滚、重复提交和关闭工作台后隔离重开仍为已确认方向。
- 新增子女草稿须锁定当前 Lineage、父 PersonId、PlacementId 及必要的排序版本或证据。切换到另一谱系、排序变化或父位置失效时，旧上下文不能静默提交；保留输入并允许在当前上下文重新发起。同一 Lineage 的 ViewMode 切换不生成独立排序或改变关系，并遵守已有草稿与焦点保护。
- 保留旧 WPF 工作台、已验收交互、显式谱系复制功能及既有测试；仅使用隔离虚构数据，不访问、迁移或修改真实用户数据库；不实施复杂多位置、嗣继、祧继或全面图表配置管理器。

## 最小技术方案（建议，待实施评审）

| 部分 | 建议方案与边界 |
|---|---|
| 数据归属 | 使用已确认的 Genealogy → Lineage 边界；人物、婚配、位置及排序写入和读取均校验当前 Lineage。谱文只作为项目下已确认的概念，具体数据模型不在本切片实现。 |
| 排序与事实 | 将 Lineage、主人和稳定婚配关系身份组成的配偶顺序独立持久化；婚配事实不保存第二套权威顺序。具体字段、版本、约束和旧隔离原型退出路径在实施设计中确定，不预设真实数据库迁移。 |
| 新增与拖动 | 新配偶只追加当前谱系的列表；拖动通过统一业务 Command 保存，原人物/关系身份及已有子女生母保持不变。首配偶限定补录和追加须在各自业务操作内原子提交。 |
| 视图 | 以当前 Lineage 的同一排序投影供横向图与吊线图读取；各自只保存允许独立的布局、缩放和视口等状态。复用既有画布体验，不把旧 Chart 配置改名后当作新领域模型。 |
| 草稿与竞争 | 绑定 LineageId、父 PersonId、PlacementId 和必要版本/证据；提交事务重新验证，谱系切换、排序变化或父位置失效拒绝过期提交并保留输入。ViewMode 切换共享事实及命令，不因视图变换静默改变排序。 |
| 异常与修复 | 顺序缺失、损坏或引用无效时保留原始数据，提供补齐/修复入口；无法确定首位时拒绝依赖该顺序的新增子女默认操作，不用画布坐标、自然顺序或随机 ID 猜测。具体修复交互待设计。 |
| 原子与幂等 | 排序、必要版本/证据和操作回执同事务；失败回滚、相同操作可安全重试，过期输入不能覆盖新结果；保留已验收输入和焦点保护。 |
| 隔离重开 | 在新建的专用隔离数据目录中支持关闭工作台再重开同一虚构样本；验证路径与文件身份，不访问真实用户库，不自动迁移旧测试库。 |

本方案**不包含同一 Lineage 下多 Chart 独立排序、向其他图表或谱系同步追加、展示视图之间复制婚配事实或图表间复制排序**。每个 Lineage 的逻辑画布不要求由旧 Chart/LineageChart 数据结构实现；是否需要其他内部标识属于待评审技术细节，不能改变业务隔离。

## 任务拆分与依赖

下列任务是实施前规划；具体完成情况以[接力](HANDOFF.md)为准：

1. **设计核查：** 清点所有旧 Position 读写和旧 Chart 假设，确定 Lineage 作用域、顺序事实分离、异常修复交互及隔离重开能力；需要新增业务规则时先确认。
2. **隔离模型与约束：** 在新测试库表达 Lineage 内独立排序、关系引用和版本/证据，Domain 不依赖 WPF、EF Core 或 SQLite。
3. **Application Command 与投影：** 实施当前 Lineage 内配偶追加、排序与显式修复；排序、版本与回执事务化，检测无效引用和竞争。
4. **子女草稿与默认生母：** 将当前 Lineage 排序、父 PersonId、PlacementId 和必要版本绑定到子女编辑上下文，覆盖 D-030、过期拒绝和失败保留。
5. **画布交互与重开：** 在现有工作台接入拖动排序、修复入口和隔离样本重开；双 ViewMode 共用业务顺序，视图状态可独立。不能把新 ViewMode 扩展成未批准的全面重写。
6. **验证与复验：** 执行隔离模型、事务、两谱系、双视图、WPF、Release 和日常回归；再用虚构样本人工复验并记录结果。

## 待执行验收矩阵

下表为验收条件，**不是本轮通过的结果**。

| 场景 | 验收条件 |
|---|---|
| 两个独立 Lineage | 同一项目下建立 A、B；在 A 新增或调整配偶/子女和排序，B 的人物、关系、位置及顺序不自动变化；不得共享人物身份。 |
| 同谱双 ViewMode | 同一 Lineage 的横向图与吊线图使用相同人物、关系、位置、排行和配偶排序；视图切换不改事实或排序，缩放/视口可独立。 |
| 新增与排序 | 新配偶仅追加当前谱系的主人列表；拖动后自动保存并重读，其他 Lineage 不变；婚配身份及已有母子关系不变。 |
| 默认生母 | 新子女按当前 Lineage 第一位有效夫妻配偶默认生母；排序调整、ViewMode 切换不改已保存的生母；无配偶及角色异常遵守既有规则。 |
| D-030 保护 | 首配偶只对符合条件的未知生母补录；已有或用户主动清空的生母不被覆盖。 |
| 错误与修复 | 缺失、损坏、无效引用、跨谱关系或角色异常保留原始数据；提供补齐/修复入口；无法确定第一位时拒绝依赖顺序的默认操作。 |
| 草稿和并发 | 草稿绑定 Lineage/人物/位置与必要版本；谱系切换、排序变化或位置失效拒绝旧提交并保留输入；同谱 ViewMode 切换不静默重置业务状态。 |
| 回滚与重试 | 排序、配偶追加、首配偶补录及子女创建按各自事务注入失败均完整回滚；重复提交不重复创建或改写事实。 |
| 数据重读与窗口重开 | 关闭连接后重读、关闭工作台后重新打开同一虚构样本均保持各 Lineage 排序及关系；不把测试目录机制用于真实数据库。 |
| 既有成果 | 保留旧 WPF 工作台及测试；Release、完整日常、相关 WPF、人工复验分别记录，未执行项不得称为通过。 |

## 剩余未决事项

- 用户显式复制谱系时是否及如何复制配偶排序，需单独确认；这不影响已确认的“不同谱系不自动共享或同步”。
- 谱文 Document 的实体与存储格式、人物传记与谱系人物的关联尚未确认；不得推断共享人物身份或实现方式。
- V1 隔离样本尚未完成传统吊线图，双 ViewMode 的实际接入范围须在实施前核对；不得把验证共同排序擅自扩大为完整吊线图重写。
- 异常排序修复的具体界面与安全流程、草稿版本实现及隔离文件重开方式待技术设计；若必须新增业务规则或改变已确认决策，先请求用户确认。
- 旧 LineageChart/既有数据过渡与真实数据库处理不在本切片自动实施；保留旧数据和旧工作台。
