# 决策契约

状态含义：**Proposed** 为待确认方案；**Accepted** 为已确认且必须遵守；**Superseded** 为已被后续决策取代。改变 Accepted 决策需先获用户确认。

## D-001 — 产品与技术基线

- **状态：Accepted**
- **决策：** 谱匠（PuJiang）是完全离线的 Windows 原生单机族谱管理系统，技术栈固定为 .NET 10、WPF、EF Core 与 SQLite。
- **理由：** 兼顾本地数据控制、Windows 桌面体验和现有原型复用。
- **影响：** 不引入云端/服务器依赖；发布、测试和恢复流程按 Windows 本地软件设计。
- **相关：** `ZupuPaiBan/ZupuPaiBan.csproj`；[架构契约](ARCHITECTURE.md)。

## D-002 — 多族谱隔离

- **状态：Accepted**
- **决策：** 一个 SQLite 数据库管理多套独立族谱，以稳定族谱标识隔离所有族谱内数据；不限姓氏。
- **理由：** 让单机用户管理多套谱系，且保留统一备份与查询能力。
- **影响：** 目标数据模型的所有族谱内实体必须具有且查询时必须约束 `GenealogyId`；跨谱关系默认禁止。
- **相关：** [目标数据模型](ARCHITECTURE.md#target-数据与关系边界)。

## D-003 — 关系与人物记录原则

- **状态：Accepted**
- **决策：** 保留生父母、配偶、过继、嗣继、房支、失考等谱系信息，并允许为每种图表指定谱系展示主线。人物可有完整配偶档案，也允许信息不完整的历史人物记录。
- **理由：** 传统族谱资料存在关系多义性与缺失，不能压缩为单一父系字段或配偶姓名文本。
- **影响：** 人物、关系、婚姻/家庭和房支必须分离建模；“主线”是展示投影规则，不得覆盖原始关系。
- **相关：** [关系模型原则](ARCHITECTURE.md#target-数据与关系边界)。

## D-004 — 世代与排行的权威性

- **状态：Accepted**
- **决策：** 谱载世代与排行为人工权威记录；系统可提供自动推导参考值，但绝不自动覆盖原始谱载。
- **理由：** 真实谱牒存在跨支、继嗣和资料误差，自动结果不能取代史料。
- **影响：** 原始值、推导值、来源和人工确认状态应可区分。
- **相关：** [P0](CURRENT_PLAN.md#p0--开发基础与数据模型)。

## D-005 — 数据交换优先级

- **状态：Accepted**
- **决策：** 优先设计内部版本化 JSON；随后完善 Excel 和 GEDCOM 交换。
- **理由：** 内部格式才能无损表达领域关系，Excel/GEDCOM 是兼容层而非领域权威。
- **影响：** 导入导出必须版本化、可预检、可报告损失；不得以现有简化格式约束核心模型。
- **相关：** [P4](CURRENT_PLAN.md#p4--数据交换与谱书制作)。

## D-006 — 数据安全与演进

- **状态：Accepted**
- **决策：** 备份恢复、关系校验、事务和自动化测试在早期开发纳入范围；使用 EF Core Migration 管理数据库演进。
- **理由：** 族谱数据不可轻易重建，批量导入与关系修改必须可验证、可恢复。
- **影响：** 不能以 `EnsureCreated` 作为正式升级方案；破坏性导入必须预检与事务化。
- **相关：** [持久化策略](ARCHITECTURE.md#target-持久化安全与演进)。

## D-007 — 重建范围与架构尺度

- **状态：Accepted**
- **决策：** 当前没有需要保留的旧版 `FamilyMember` 数据库，P0 不实施该旧模型的数据迁移。保留有价值的 WPF 界面和功能原型，允许重新设计核心模型；避免微服务化、无必要多工程拆分和过度重构。
- **理由：** 现有原型的单父系模型无法承担目标领域，且无遗留数据约束。
- **影响：** 可在单桌面应用内渐进替换持久化与领域层，但须保留清晰模块边界。
- **相关：** [当前与目标边界](ARCHITECTURE.md)。

## D-008 — 传统吊线图细则

- **状态：Proposed**
- **决策：** 传统吊线图的地域谱式、具体版式模板及复杂关系的视觉表达尚未确认。
- **理由：** 这些规则直接影响布局算法、分页和验收样张。
- **影响：** 不得把现有“Vertical”树图等同于传统吊线图；P3 实施前须确认规则或提供样张。
- **相关：** [P3](CURRENT_PLAN.md#p3--传统吊线图)。

## D-009 — 项目名称、仓库与分支策略

- **状态：Accepted**
- **决策：** 项目中文名为“谱匠”，拼音/产品标识为 `PuJiang`；Git 远端为 `https://github.com/miozen/PuJiang.git`。`main` 为稳定分支，`dev` 为日常开发分支；需要隔离的较大功能使用 `feat/*` 分支。
- **理由：** 统一产品标识、仓库归属与跨电脑协作基线。
- **影响：** 新增产物、测试工程和程序集使用 `PuJiang`；现有 `ZupuPaiBan` 源码目录与命名空间暂作为渐进重命名范围，不能在无专项验证下机械替换。
- **相关：** [开发协议](../AGENTS.md)；[接力状态](HANDOFF.md)。

## D-010 — 工程质量、数据目录与发布基线

- **状态：Accepted**
- **决策：** 使用 `PuJiang.slnx`、.NET SDK 10.0.402、xUnit 和真实 SQLite 临时文件作为统一 Windows 开发入口；GitHub Actions 在 Windows runner 执行 restore/build/快速测试。正式数据位于 `%LOCALAPPDATA%\\PuJiang`，与程序目录分离；正式发布目标为 `win-x64` self-contained。
- **理由：** 让离线桌面软件具备可重复构建、可隔离验证和可维护的数据边界，而不引入云端或复杂平台。
- **影响：** 测试不得触碰用户目录或真实族谱数据；性能/UI 验收独立运行；正式结构变更仍须遵守 D-006 的 Migration 和备份要求。CI 配置完成不等于远端已通过。
- **相关：** [开发与运行规范](OPERATIONS.md)；[Windows 构建、测试与发布](ARCHITECTURE.md#windows-构建测试与发布)。

## D-011 — 成员树优先的操作体验

- **状态：Superseded（主入口及最终左栏定位；过渡成员树与快捷入口暂保留，见 D-026）**
- **决策：** 正式族谱人物管理以成员树中的便捷操作为方向，保留右键新增、双击编辑和工具栏快捷入口；当前目标模型的列表及姓名输入区可作为过渡验证界面。
- **理由：** 用户确认成员树上下文操作更符合使用习惯，同时允许当前阶段继续通过临时界面验证目标模型。
- **影响：** 后续将成员树及快捷入口逐步接入按 `GenealogyId` 隔离的目标模型；父子关系等复杂变更须遵守现有事务与关系校验契约。过渡界面不得被描述为最终完成的成员树操作。
- **相关：** [目标图与数据边界](ARCHITECTURE.md#target数据与关系边界)；[阶段计划](CURRENT_PLAN.md)。

## D-012 — 内部 JSON 导入冲突与副本策略

- **状态：Accepted**
- **决策：** 内部版本化 JSON 导入默认先预检并失败关闭：发现不能安全处理的冲突、不兼容版本或无效引用时，拒绝写入并返回明确原因。导入现有族谱时不得静默覆盖、删除或自动合并人物、关系、婚配及房支；同名、同世代或同排行本身不构成同一人物或冲突。后续仅以显式“导入为新族谱副本”支持可选导入：生成新的族谱 ID，并完整重映射人物、关系、婚配、房支及其内部引用。所有导入写入必须事务化，失败不得留下部分数据；应保留导入来源及必要的格式版本信息，以支持后续交换演进与历史追溯。本阶段不开发冲突合并系统。
- **理由：** 族谱中重复姓名、世代和排行普遍存在，自动匹配会损害史料；默认拒绝和原子写入能在交换能力演进期间保护既有数据。
- **影响：** 持久化导入须将结构/版本/引用校验与数据库冲突检查置于写入前，冲突报告需可区分冲突类型；副本导入实现时必须建立完整 ID 映射，不能复用来源 ID 或依赖名称猜测。现有 JSON 预检仍只做内存映射，不得据此宣称已经具备导入能力。
- **相关：** D-002、D-005、D-006；[P0](CURRENT_PLAN.md#p0--开发基础与数据模型)。

## D-013 — 外部格式导入损失确认策略

- **状态：Accepted**
- **决策：** Excel/GEDCOM 等外部兼容格式始终导入为新的目标族谱，绝不写入、覆盖或合并既有族谱。预检错误（不兼容版本、结构、引用或无法验证的数据）一律阻断写入；可安全映射但存在字段/关系损失时，先展示分类损失报告，只有用户在独立确认步骤明确接受损失后才允许创建新族谱。导入来源记录保存 profile、格式版本和原始文件 SHA-256 指纹，不保存本机文件路径。
- **理由：** 外部格式不能完整表达目标谱系模型；将不可逆映射与数据写入分离，避免静默丢失或误合并。
- **相关：** D-002、D-005、D-006、D-012；[P0](CURRENT_PLAN.md#p0--开发基础与数据模型)。

## D-014 — P1 启动与专项验收调整

- **状态：Accepted（2026-11-02，用户确认）**
- **决策：** P0 已达到 P1 启动条件，但原验收项并未全部完成；生产恢复延期至正式使用真实数据前的专项验收，完整主线投影纳入 P1/P2 依赖计划。暂停按谱候选切换、测试门闸与极端并发时序的主动扩展，生产继续使用全库代数；自动合并、生产恢复及按谱候选切换保持关闭。
- **理由：** 优先交付可操作的族谱管理功能，同时保留未完成的数据安全与投影工作。
- **影响：** 新功能须有可操作验收，测试聚焦正常路径、数据隔离、必要失败路径和现有回归；仅出现可复现高风险缺陷、影响交付的回归或用户明确要求时重启深层专项测试。此调整改变 D-006 的阶段安排而不取消恢复范围；原范围变更记录保留。
- **替代方案：** 继续以全部 P0 原验收和门闸专项作为 P1 前置条件，已由用户决定不采用。
- **相关：** [阶段计划](CURRENT_PLAN.md)、[接力状态](HANDOFF.md)。

## D-015 — 非空房支删除与内容安置

- **状态：Accepted（2026-11-02，用户确认）**
- **决策：** 删除非空房支前预览直属子房支和直属人物，分别显式选择同谱安置位置；子房支可移至顶层，人物可选择未归属。确认后在一个事务中核对受影响内容与目标、安置并删除所选房支；子树、人物档案及图关系保留。冲突、过期或失败时整体拒绝，不自动合并或级联删除。
- **理由：** 房支删除会改变谱系分类，须让使用者明确决定数据去向。
- **替代方案：** 禁止删除非空房支，要求逐项手动处理后再删除；用户选择预览和事务安置方案。
- **影响：** 界面需列出受影响内容及目标并二次确认，包含隔离和失败回滚验收；不改变 D-014 的生产恢复等边界。

## D-016 — 父母关系类型原地更正

- **状态：Accepted（2026-11-02，用户确认）**
- **决策：** 同一对人物的生物父母、养父母及继嗣父母关系允许经明确确认原地更正类型，保留关系 ID、双方、备注、来源及主线标记；不将配偶或失考纳入，也不更换双方或自动推导其他记录。
- **理由：** 更正误录类型时保留既有记录身份与谱载资料。
- **替代方案：** 解除原关系后另建记录；会改变身份并需重新录入资料。
- **影响：** 须检查同谱、原快照、重复和父母环路，并在事务内失败关闭；不改变 D-014 的边界。

## D-017 — 补全未详婚配的另一方

- **状态：Accepted（2026-11-02，用户确认）**
- **决策：** 用户可显式选择同谱现有人物，原地补全另一方未详的婚配；保留婚配 ID、类型、时间文字和备注，双方按现有无向配对规则规范排序。不得自动创建人物关系或合并记录。
- **理由：** 后续确认人物身份时保留已有谱载婚配及记录身份。
- **替代方案：** 解除旧记录后新建婚配；会改变记录身份并需重新录入资料。
- **影响：** 须确认双方并检查旧快照、同谱、自身、重复及全库代数；完整婚配更换或清除对方不在此范围，失败不写入。

## D-018 — 婚配类型原地更正

- **状态：Accepted（2026-11-02，用户确认）**
- **决策：** 用户可经明确确认在婚姻、伴侣关系及类型未详之间原地更正已有婚配类型，保留 ID、双方（含另一方未详）、时间文字和备注；不更改人物、不自动合并或推导其他记录。
- **理由：** 更正谱载类型时保留记录身份和已有资料。
- **替代方案：** 解除旧婚配后重建，须重新录入资料且改变记录身份。
- **影响：** 须检查旧快照、参与者、同谱、全库代数及现有重复规则，失败关闭；不改变 D-014 边界。

## D-019 — 上系失考后发现上系

- **状态：Accepted（2026-11-03，用户确认）**
- **决策：** 保留原上系失考记录及其备注和来源，由用户显式新增同谱父母关系；两条原始记录同时展示，不自动转换、合并或推导。
- **理由：** 保留曾记载失考的谱载证据，同时记录新发现的上系。
- **替代方案：** 将失考记录原地转换为父母关系；会改变原始记录的含义。
- **影响：** 沿用同谱、自身、重复及循环校验，关系新增确认前选择失效时拒绝；不改变 D-014 边界。

## D-020 — P2 千人树形浏览性能验收建议

- **状态：Accepted（2026-11-03，用户确认）**
- **决策：** 以 [P2 树形基线](P2_TREE_BASELINE_2026-11-03.md) 的本机和固定千人目标模型样本为参考，沿用其窗口打开、姓名/ID 定位及展开的计时边界。新进程首次打开测 3 次、最大值不超过 1,000 ms；同进程重复打开测 20 次，p95 不超过 500 ms；姓名和 ID 定位各测 20 次，p95 各不超过 500 ms、最大值各不超过 1,000 ms；根节点展开测 20 次，p95 不超过 200 ms。20 次的 p95 使用排序后第 19 个值，保留原始数据和最大值。
- **理由：** 基线样本量小且存在波动；该阈值为参考机上该样本的初步验收目标，不推断其他设备表现。
- **边界：** 首次打开不含进程/主窗口启动，不是操作系统冷缓存；搜索不含逐字键入或人工反应，布局完成不等于物理帧呈现。深链、宽分支、其他设备和图形渲染需另行测量；现有 3/10 次样本不能直接宣称通过上述 20 次验收。Performance/UI 专项及人工视觉验收分别执行。
- **替代方案：** 暂不设阈值，先扩展多设备和多谱形样本；用户确认采用上述参考范围。

## D-021 — 树形世系的会话路径高亮建议

- **状态：Accepted（2026-11-03，用户确认）**
- **决策：** 在现有只读树形浏览中，选择或搜索定位人物时，突出该人物和沿当前已选父母边可到达的祖先节点；在待选或未记录上系处停止并说明边界，不推断始祖。选择其他人物或更改选线时重算，清除选择、切谱或刷新时清除高亮；折叠不改变选线，不为高亮自动展开，搜索定位保留现有自动展开行为。
- **理由：** 利用已有投影解释当前路径，且不修改或保存原始关系。
- **影响：** 选中人物与路径祖先须有可区分的视觉状态；隔离测试覆盖多分支、未决、失考、选线切换、搜索、折叠和失效，WPF 真实窗口验收，人工视觉验收另记。此功能不构成完整图形世系图或按图表配置。
- **替代方案：** 只提供已有单人物上系文字预览，推迟树形路径提示。

## D-022 — 按图表保存主线配置

- **状态：Accepted（2026-11-03，用户确认）**
- **决策：** 每个族谱可有多份具稳定 ID 的图表配置，在 SQLite 保存用户显式选择的父母关系及身份快照；选择只改变展示投影，不改变原始关系。唯一候选仍自动展示，多候选需显式选择，未选择保持待选；保存由用户显式触发。
- **失效处理：** 打开时核对同谱、人物、关系 ID、双方及关系类型；失效项保留旧信息、不应用，用户须显式重新选择或清除。全库代数变化时，即使身份快照相同也须复核后才能应用；保存事务核对全库代数及配置版本，冲突拒绝且不覆盖原配置。配置引用为可失效历史标识，不阻止关系解除或静默级联删除选线。
- **迁移和备份：** 通过 EF Migration 新增空配置表，不从原始关系推断配置；沿用迁移前数据库快照。配置随数据库专用备份保存；严格迁移集合及结构预检保持不变，旧结构包不可直接通过新程序预检，生产恢复仍关闭。
- **理由与替代：** 独立图表配置允许同谱采用不同主线，避免数据库与外置文件错配；不采用将选线写入原始关系或外置 JSON。全库代数带来无关修改也须复核的保守成本，不防恶意篡改或替换数据库。
