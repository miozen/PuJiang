## P0 — 开发基础与数据模型

- **Goal：** 建立可安全演进、可测试的多族谱领域与本地持久化基础。
- **Scope：** Windows 原生构建验证；开发规范与接力机制；新族谱数据模型；多族谱隔离；人物、亲属、婚姻、继嗣及房支模型；EF Core Migration；完整性校验；基础备份恢复；自动化测试基础。
- **Completed：** 本仓库已具备 WPF/EF Core/SQLite 原型；已建立开发协议、决策、架构、计划与接力档案及 P0-0 工程基线。已新增目标模型、复合外键隔离、首个 Migration、关系校验与测试；批量关系校验涵盖同批次和已有关系构成的循环及重复失考。新增按单谱读取人物、关系、婚配和房支的不可变原始数据快照及目标人物只读关系清单，不选择展示主线。WPF 已接入目标族谱创建、会话内切换、按谱人物列表、姓名及基础档案编辑、无关系人物确认删除，以及生物子女新增、已有子女关联、列表和生物父母关系确认解除；旧 `FamilyMember` 功能独立保留。已有数据库有待执行迁移时，先生成并校验 SQLite 数据库快照；新版本实例持有数据目录独占锁。PDF/XPS 均先写入所选目录内临时文件再发布；隔离 UI 测试已覆盖发布前失败时目标和临时文件清理以及正常退出竞争。Excel/GEDCOM 的旧成员整表替换及协作树追加均改为事务提交，写入失败回滚且导入引用先验证。内部 v1 JSON 可预检并持久化导入为来源 ID 尚未存在的新目标族谱；结构、版本、引用及各类记录 ID 冲突均在写入前按类型报告并拒绝，不按姓名、世代或排行自动匹配，完整图数据和来源追溯记录在一个事务内写入或回滚；追溯保存来源种类、格式版本、来源族谱 ID、文档指纹及导入时间，族谱名称不再强制唯一。已确认内部 JSON 默认预检失败关闭、禁止静默覆盖/合并、后续仅允许显式副本导入的冲突策略；跨进程、独占句柄与 WPF 子进程测试已在同一禁止并行集合中运行，以消除 CI 的启动/回收竞争。
- **Completed（本检查点）：** 文件菜单已接入独立“导入内部 JSON…”模态入口；默认模式预选且预检不通过即禁用提交，副本模式要求显式切换、显示名称和二次确认。导入成功后刷新并选中新族谱；取消、拒绝和失败不改变当前选择。隔离原生文件框取消测试验证正常退出仍等待操作结束。
- **Completed（本检查点）：** ExcelLegacyV1 与 GEDCOM-5.5.x 已具备只读版本 profile 预检和目标模型内存映射；不兼容结构或坏引用失败关闭，未安全映射的配偶姓名/标签以损失报告返回，不写数据库。
- **Completed（本检查点）：** 已按 D-013 实现 Excel/GEDCOM 外部兼容格式的事务化持久化导入服务：预检错误零写入；有损映射须由调用方显式接受；每次均克隆为新族谱并重映射全部内部 ID；族谱、图数据与含 profile/版本/原始文件 SHA-256 指纹的来源记录在同一事务写入，失败不留部分数据或本机路径。
- **Completed（本检查点）：** 隔离 SQLite 已在外部 GEDCOM 导入的婚配写入点注入失败，确认此前暂存的族谱、人物、关系、婚配及来源记录全部回滚为零残留。
- **Completed（本检查点）：** 外部 Excel/GEDCOM 导入在预检完成后会两次复核原始文件 SHA-256（最终一次紧邻事务写入）；读取失败、删除、替换或内容篡改均以 `SourceChangedAfterPreflight` 拒绝，且不创建图数据或来源记录。隔离 SQLite 已分别验证 GEDCOM 替换和 Excel 篡改的零残留。
- **Completed（本检查点）：** 完整双人婚配按稳定 ID 顺序作为无向配对去重，反向输入不再成为第二条婚配。内部 JSON 和 GEDCOM 预检会在映射前拒绝反向重复；持久化图批次遇到该冲突时回滚暂存人物和婚配记录。单方资料不完整的婚配不受此规则影响。
- **Completed（本检查点）：** 隔离 SQLite 以两个独立 `DbContext` 复现陈旧预校验竞争：双方均在空视图通过校验后，人物关系与规范化婚配的第二次提交均由数据库唯一索引拒绝，最终各只保留一条记录。
- **Completed（本检查点）：** 隔离 SQLite 已覆盖删除无关人物与关系/婚配写入的两个提交顺序：删除先完成时陈旧写入由复合外键拒绝且零悬挂引用；写入先完成时原子删除条件拒绝移除人物并保留完整记录。
- **Completed（本检查点）：** 离线备份预检已在隔离副本校验 SQLite 完整性、外键完整性、迁移集合和结构；校验和正确但含外键违规的包、迁移差异或结构差异均失败关闭，且活动数据库与原备份包字节不变、预检临时文件清理完成。
- **Completed（本检查点）：** 目标模型成员树工具栏已新增显式“新增人物关系”和“新增婚配”入口。对话框仅列出当前 `GenealogyId` 中、非主体的人物；提交时 ViewModel 重新校验当前选中人物与对方候选范围，再进入既有关系/婚配领域校验和 SQLite 复合外键。新增不自动推导另一类记录、合并人物或覆盖既有数据；失考关系明确不选对方。隔离 SQLite 覆盖跨谱候选与陈旧选中人物的零写入，STA WPF 子进程覆盖对话框候选隔离及正确持久化。
- **Completed（本检查点）：** 目标模型成员树工具栏已新增“解除关系/婚配”入口。对话框只显示当前人物参与的同谱记录，切换记录会重置确认，必须选择精确记录并勾选后才可提交。关系与婚配各使用同时限定 `GenealogyId`、记录 ID 和当前参与者的一条 SQL 删除；跨谱、陈旧/重复解除或底层失败均零写入，且不删除人物或另一类图记录。隔离 SQLite 覆盖成功、跨谱/陈旧拒绝及触发器失败；STA WPF 子进程覆盖确认门槛和解除关系时保留婚配。
- **Completed（本检查点）：** 隔离 STA WPF 子进程在目标婚配新增的 `INSERT` 及人物关系解除的 `DELETE` 已进入执行时请求真实主窗口正常关闭；排空期间新操作和第二目录租约均被拒绝，放行后既有写入以单一完整结果提交、主窗口关闭并可独占打开 SQLite 文件。所有数据均位于临时测试根目录；未触碰正式数据，未接入或模拟生产恢复。
- **Completed（本检查点）：** 隔离 SQLite 在人物档案更新、关系新增、婚配新增和婚配解除各自已进入 SQL 执行时切换族谱。写入始终仅作用于发起时已校验的原族谱记录，切换后的当前人物和列表不被旧操作回填；另一族谱零图数据写入。该测试不做自动合并，不触碰正式数据或恢复路径。
- **Completed（本检查点）：** 隔离 STA WPF 子进程在成员树档案更新、右键新增生物子女、已有子女关联和生物父子解除的 SQL 已暂停后切换到另一族谱。四种原子写入均只提交至发起时已校验的原族谱，切换后的人员、关系及当前视图不被陈旧操作回填，另一族谱无错误图数据。选择快照遇到短暂 SQLite `BUSY`/`LOCKED` 时以新上下文有限重试，耗尽则保持失败关闭；未启用自动合并或生产恢复，全部数据位于隔离临时目录。
- **Completed（本检查点）：** 隔离 SQLite 以真实 `BEGIN EXCLUSIVE` 锁验证成员树切换的 `BUSY` 重试耗尽：界面清空失效选择并显示失败，不携带旧谱数据；解除锁后可重新加载，数据库不产生写入。档案、右键新增子女、已有子女关联和父子解除的触发器失败均保持原有图记录及成员树/当前选择不变，新增子女的事务不遗留暂存人物。
- **Completed（本检查点）：** 成员树档案、右键新增子女、已有子女关联和父子解除在 SQL 写入已成功后注入后续读取失败：写入仍按事务完整提交，刷新复用有限 SQLite 忙锁重试；耗尽后清空可能陈旧的树、以“已保存/已建立/已解除，但刷新失败”报告实际状态，解除失败后重新选择可加载真实图数据。全程不自动合并、不触碰正式数据或生产恢复。
- **Completed（本检查点）：** 目标人物关系/婚配的新增及显式解除在 SQL 写入已成功后注入后续读取失败：关系和婚配图记录按原子写入真实提交，成员树清空而不展示陈旧关系，状态保留“已新增/已解除，但刷新失败”且不被成功文案覆盖；解除故障后重新选择可加载实际结果。刷新与族谱选择共用有限 SQLite 忙锁重试，未启用自动合并或生产恢复。
- **Completed（本检查点）：** 关系/婚配解除候选读取复用有限 SQLite 忙锁重试；耗尽时不返回候选且零删除。读取期间选择失效时拒绝返回陈旧候选，随后可切换族谱重新读取；候选与删除始终按当前 `GenealogyId`、记录和参与者约束。
