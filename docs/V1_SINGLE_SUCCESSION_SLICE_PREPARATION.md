# V1 单一承嗣关系隔离切片准备

状态：用户已确认首批场景与异常保护，四份契约已定向协调，并批准隔离实施；对本次隔离样本体验反馈“应该符合预期了”。保留 WPF 三栏工作台，只使用独立虚构数据；按 D-033 项目完成前不做旧数据兼容或迁移。当前实施范围及验证以[阶段计划](CURRENT_PLAN.md)和[接力](HANDOFF.md)为准；下文保留实施前核对与验收设计的历史语境。

## 首批用户方向与示例

用户确认首批选择谱系中**已有的丙**，选择“挂接为嗣子”后选择嗣父乙；不把新建同名人物作为承嗣。丙在乙处追加到对应性别组末尾，之后可调整。为便于讨论，以当前同一 Lineage 的甲（生父）、乙（拟定嗣父）、丙（已录入人物）以及丙已有的后代为例。该示例不预设丙与乙的世代差、年龄、房支或亲属关系；嗣父人选须由编修者明确选择。

用户已确认首批以丙已有明确普通出生位置、唯一当前承接位置，乙与丙均在同一谱系且乙有有效位置为场景；丙已有或暂无后代均纳入，乙可已有子女并按已确认规则追加。没有出生位置、已有多段嗣继等其他情形暂不预设。

## 现有 V1 现状及需准备的缺口

- [领域对象](../PuJiang.Domain/Entities.cs)已有独立 Person 和 Placement，但当前亲属事实仅实现生父母及婚配；没有可直接表达嗣继、位置身份及当前唯一后代承接的完整 V1 业务模型。仅给同一 Person 增加另一个 Placement 不足以确定关系身份与承接规则。
- [隔离映射](../PuJiang.V1.Persistence/IsolatedTestDatabase.cs)允许位置引用人物并按谱系约束，但现有映射并未由此证明嗣继事实及唯一有效承接约束已经实现；本次不设计或执行数据库变更。
- [子女投影](../PuJiang.V1.Persistence/IsolatedChildStore.cs)要求父位置对应明确生父，[排行校验](../PuJiang.V1.Persistence/IsolatedChildOrderStore.cs)也检查普通生父与父位置一致；直接将嗣父当生父会丢失事实或使读取失败。画布虽以 PersonId + PlacementId 保持焦点，现有 [显示与结构入口](../ZupuPaiBan/Views/V1FirstRootWindow.cs)仍以普通子女投影为输入，承嗣引用与后代承接尚未接入。
- [普通挂接](../PuJiang.V1.Persistence/IsolatedBranchStore.cs)替换生父、调整世代并拒绝多位置；它不是嗣继命令。D-038 删除、拆支及普通新增子女／兄妹等入口也不能假定已支持嗣继位置，需在实施前梳理保护与复用边界。
- 旧工作台已有关系模型、部分过继录入或跨代布局成果可供只读对照；按 D-033 不兼容旧数据，旧行为不能自动覆盖新契约，也不能当作 V1 已实现。

## 首批依赖与剩余事项

1. **实际示例与来源位置：** 用户已确认首批覆盖丙有明确普通出生位置和唯一当前承接位置、乙有同谱有效位置的情形；丙有或无后代、乙已有子女均纳入。其他来源和复杂情形不在首批，不改变契约支持范围。
2. **入口与确认：** 用户已确认选中丙、选择“挂接为嗣子”并选择乙后，先显示对生父处引用、嗣父位置和后代承接的影响，确认后保存；取消不提交。具体展示与失败保护按现有工作台细化。
3. **嗣父位置排行：** 用户已确认丙追加至乙处对应性别组末尾，之后可调整；不得依据出生位置排行、画布坐标或数据库自然顺序猜测，丙在甲处排行与乙处排行分别管理。排序异常不得猜测；无法安全确定时保留原值并提示核实。
4. **嗣母及默认关系：** 用户确认首批支持记录嗣母，丙原有生母关系保留，二者为不同关系。嗣父多位配偶时默认持久化排序第一位，之后可修改；无配偶允许先承嗣、嗣母暂不记录，之后新增第一位配偶时自动补录，用户主动清空过嗣母的情况除外。后续修改时候选仅为乙的有效配偶，并允许清空；丙的生母不变。无效排序、缺失引用及角色不一致时保留原始数据并拒绝依赖该默认值的提交，不将异常当作无配偶。
5. **明确状态与异常：** 乙是丙本人／后代、跨谱、失效位置、已有其他有效承接位置、原位置不完整或多段嗣继等，须按契约校验。首批可建议对超出单一场景或无法安全确定范围的情况提示并拒绝，不自行建立历史状态转换、循环判定例外或自动迁回。
6. **已有入口安全：** 在承嗣位置新增子女、兄妹、修改排行、拆支、删除、普通挂接和世代更正如何保护当前位置及原生父事实，需要逐项核对与决定首批开放或明确禁用；不能因为一个创建操作实现就假定其他复杂操作已支持。
7. **视图、跨代与可见性：** 横向视图下生父处引用如何标识和定位、嗣父处如何承接完整后代；同一 PersonId 不同 PlacementId 焦点和缩放定位须验证。传统吊线图为同一 Lineage 另一 ViewMode，未实现的视图不因本切片自动宣称完成。

## 嗣母候选、异常保护与契约协调记录

### 已确认规则与处理边界

- 嗣母是独立于生母的事实；选择已有丙承嗣不改其原生父母。嗣父多配偶时，按当前 Lineage 的持久化配偶顺序默认第一位；用户可从嗣父的有效配偶中更改或清空。无配偶允许嗣母暂空，之后新增第一位配偶时补录，用户主动清空过嗣母的情况除外。该清空状态应能与生母状态分别表达，不能共用一个标志而互相覆盖。
- D-031 已确认首配偶不能按坐标或数据库自然顺序猜测，排序损坏时保留原始记录并提供修复入口。**用户确认的承嗣保护**：无法确认第一位有效配偶、配偶身份缺失或与嗣母角色不一致时，提示核实并拒绝依赖该默认值的提交；不改配偶性别、不猜测、不删除原始事实。无任何配偶与排序异常需分别识别，不能将异常伪装成无配偶。具体修复入口复用方式与测试在实施中验证。
- 先承嗣再新增首配偶的建议事务边界：仅核对新配偶所属嗣父及对应有效嗣子位置、嗣母未记录且非主动清空的人物，新增配偶和符合条件的嗣母关系原子保存；失败回滚。是否覆盖多个位置、历史嗣继和其他复杂情形仍遵守契约并排除在首批建议外，不因该方案补完未决规则。
- 建议保留已保存嗣母不因配偶排序调整或新增加的第二位及更多配偶而改变；这是沿用已确认配偶事实与排序分离原则提出的承嗣建议，尚未作为用户对嗣母的独立确认。

### 已确认首批场景及保护

用户已确认先以当前谱系已有的丙为来源，丙有明确普通出生位置、唯一当前承接位置；乙已有有效父位置，可已有子女，丙可以有后代，也可没有后代。选择丙后选择“挂接为嗣子”，指定乙，展示影响并确认。发生过期、取消或失败时保留原关系、位置与已录入状态；来源或目标不在同谱、失效、重复、形成循环，或不能确定承接唯一性时按现有领域校验阻止。此段为已确认的首批范围，不自动否定契约允许的其他情形。

普通新增、兄妹、拆支、删除、排行、世代更正及普通挂接现在以单位置／生父事实为前提；**实施前置**是逐项确定哪些能安全复用、哪些对承嗣位置应禁用并提示，避免对原生父事实或非承接位置误操作。不能以“保留旧工作台”为由绕开这一保护，也不把全部复杂编辑纳入首批。
