# 按谱解除候选切换方案（待批准）

## 状态与范围

这是 P0 可审阅的提案，不是生产切换授权、已实现契约或新的 Accepted 决策。当前 `GenealogyDataService.GetGraphSnapshotAsync` 在一个读事务读取全库代数与图；关系、婚配候选通过全库代数、记录和姓名条件执行单条删除。V1 按谱活动/墓碑表及触发器与全库触发器并行，但生产候选仍使用全库代数。只讨论 `TargetLinkRemovalCandidate` 的显式关系/婚配解除；生物父母解除等其他入口不因本提案自动改变。自动合并及生产恢复保持关闭。

目标是在维持同谱陈旧候选保护和失败关闭的前提下，使另一谱的正常写入不再仅因全库代数变化而拒绝原谱确认。此目标不是削弱记录、姓名、参与者或选择范围检查，也不承诺隔离其他谱的损坏：现有 `ScopedUnlinkGenerationV1.GuardSql` 验证全库活动行、墓碑和版本化结构，其他谱损坏仍可能使整个守卫失败。

## 候选身份与生命周期

建议候选使用不可混淆的版本化令牌，至少包含：策略标识（例如 `GlobalV1` 或 `ScopedV1`）、`GenealogyId`、对应策略的整数代数、应用实例内的策略会话标识；继续保留主体、记录快照、显示姓名及族谱/人物选择版本。不要仅重用一个无类型 `long`，也不要把两种代数的数值互相解释。具体类型和 API 命名属于待评审实现细节。

同一应用实例在候选创建与确认期间必须具有稳定策略会话标识。策略切换或回退要先阻止新的候选操作、完成或拒绝在途操作，再递换会话标识并丢弃候选、要求重新读取；旧策略、旧会话、未知版本、缺失值或跨谱令牌一律在写入前拒绝。刷新、切谱或切换人物仍维持现有选择版本检查，即使切回也不能恢复旧候选。该会话标识只约束参与该协议的应用实例，不能识别外部进程直接替换数据库、修改代数或删除再恢复触发器。

候选为内存短生命周期对象，不持久化，不跨应用进程传递。程序重启、批准的数据库替换/恢复、迁移降级再升级以及任何基线可能重置的操作，都必须使所有既有候选失效，不能依赖代数碰巧不同；实际生产恢复尚关闭。对不遵守协议的外部程序替换数据库或有意篡改，当前机制不能保证防护。降级再升级把活动谱基线重置，尤其不能以数值相同推断候选有效。

## 读取与解除契约

1. 未来按谱策略下，在同一个 SQLite 读事务内，以参数化当前 `GenealogyId` 执行版本化 V1 guard，读取唯一有效代数，再读取该谱人物、关系和婚配快照；显示姓名及候选数据必须来自该事务。缺失或无效代数、对象定义损坏、读取错误或忙锁耗尽时失败关闭，不返回部分候选、不回退到全库值；空值与异常不得误表示为代数零。
2. 解除前验证令牌策略、会话、族谱、主体和选择版本。关系和婚配分别使用一条原子 SQL `DELETE`，同时限制族谱、记录 ID、参与者、候选快照全部持久化字段、双方存在且姓名一致，并通过参数化的按谱 V1 guard 比较令牌代数。可空的对方、姓名及字段必须保持现有 SQL null 语义。不得先单独读守卫、再无条件删除，也不得只按姓名匹配。
3. 按谱策略下不将全库代数**数值**作为旧候选过期条件，否则无关谱的写入仍会使其过期；全库与按谱触发器继续并行维护。是否还需在读取和删除时验证全库结构而不比较其数值，须作为待实现的具体守卫契约明确并以隔离测试验证，不能假设现有 `ScopedUnlinkGenerationV1.GuardSql` 已验证全库触发器。
4. 影响行数为 1 才报告已解除；零行报告陈旧并按现有流程刷新；结构缺失或数据库/锁错误报告失败，不能报告成功。写入已提交但刷新失败时保留已解除的事实、清除陈旧视图并允许重新选择；后续读取不得错误回填到新的族谱或人物选择。
5. 在确认窗口打开期间保持正常退出协调：已登记的读/删除按现有排空协议结束，新操作拒绝；不得借切换策略绕过现有协调。此要求不声称已解决所有进程或外部文件操作。

## 切换与回退提案

| 状态 | 候选读取和解除 | 允许转换条件 |
|---|---|---|
| 当前 `GlobalV1` | 全库代数；保持当前生产行为 | 正式契约、隔离验收与明确授权完成后，才可计划切换 |
| 待实现的 `ScopedV1` | 按谱代数及上述单条删除守卫；全库触发器仍维护 | 需要排空相关操作并使旧会话候选失效 |
| 回退 `GlobalV1` | 全库代数；不得继续消费按谱候选 | 同样先排空并使切换前候选失效，重新读取 |

本表只描述逻辑状态，不建议在未经设计与授权前添加运行时开关。全库保留使回退有数据基础，但**不等于回退已经安全实现**：新旧进程并存、外部结构写入、数据库替换、迁移恢复和确认窗口中的操作仍需独立验证；回退不是执行 Migration `Down`，也不是数据库恢复。

测试专用门闸审计补充：切换回调可能已产生副作用后才失败或收到取消，不能仅凭门闸内旧策略值判断实际状态。建议此时将状态标记为不确定并持续拒绝操作；在途操作排空后，由显式恢复过程检查并协调实际状态，验证成功才轮换会话并重新开放，验证失败或异常继续关闭。取消在排空后、回调之前应阻止回调；回调已产生副作用但尚未提交内部策略时收到取消应进入不确定状态；切换已完成后再取消不能倒退已完成的切换。提交点附近的并发取消须有明确线性化规则和测试。测试原型只用内存字符串模拟外部状态及人工验证，不提供持久化记录、真实副作用协调或跨进程保证；回调挂起、进程终止及不可验证状态的处置仍需单独设计。

## 隔离验收矩阵

所有场景使用 GUID 独立临时数据库，先验证 `GlobalV1` 基线，再在测试专用或获准后的实现中测试 `ScopedV1`；同一项覆盖关系与婚配，并明确写入的谱、提交/回滚和最终记录数。现有原型、现有 V1 schema 与 WPF 全库测试是先前证据，不能自动视为新候选路径验收通过。

| 类别 | 场景与期望 |
|---|---|
| 策略/生命周期 | 两种令牌不得混用；同值跨策略、未知策略、旧会话、切换后回切、重启和模拟替换/基线重置的候选均零删除；新候选可按当前策略执行。 |
| 事务读取 | 暂停 guard 与人物/关系读取之间的读事务，竞争同谱和跨谱写入，快照的姓名、记录及代数必须来自同一一致视图；失败不返回部分候选。 |
| 同谱 ABA | 姓名、所有候选字段先改后还原，关系/婚配及人物删除重插、族谱同 ID 重建后，旧候选零删除；新候选按预期可解除。 |
| 跨谱隔离 | 无关谱普通写入或批量导入提交不使原谱候选仅因全库变化过期；回滚不改变代数。合法跨谱移动使旧、新谱代数变更；不允许跨谱非法引用。 |
| 守卫故障 | 活动/墓碑缺失、重叠、类型/范围损坏、溢出、触发器丢失或同名替换、表缺失，以及另一谱损坏均失败关闭；分别断言零删除和实际错误/提示。 |
| 原子竞争 | 在删除 SQL 执行前竞争同谱修改、另一谱提交和回滚；验证精确受影响行、记录和双代数与提交一致，不能出现先校验后删除的窗口。 |
| WPF 与退出 | 真实候选确认窗口覆盖切谱/切人再切回、候选外部修改、忙锁耗尽、删除成功后刷新失败及重新选择；读/写在途请求正常退出，验证排空、最终事务与状态。 |
| 演进和回退 | 旧库升级、迁移失败、真实受保护表与索引/双轨触发器重建、新旧备份预检、两种策略间切换/回退和旧候选失效；对旧版程序共存明确模拟范围，不冒充真实旧版本验收。 |
| 性能 | 按谱数、每谱人物及墓碑规模测量 guard、候选读取和解除及写入开销，与全库基线交替比较；记录数据集、环境、样本及阈值，避免把微基准当作完整应用验收。 |

执行顺序建议先在测试专用路径固定令牌和 SQL 语义并验证失败关闭，再完成 SQLite、独立进程和 WPF 隔离测试及本地日常回归；阶段验收确认对应远端 CI。评审可单独批准进一步设计或测试，**不能将本提案视为批准生产切换**。
