# V1 普通人物显式世代与跨代显示切片准备

> 历史准备记录：下文关于普通子女可逐人填写或允许跨代的表述已被用户验收纠正取代，不再作为实施依据。当前规则见 [D-036](DECISIONS.md#d-036--谱系人物均有世代)，实际验证见 [HANDOFF](HANDOFF.md)。

## 已确认规则与适用范围

| 依据 | 已确认内容 | 与本切片的关系 |
|---|---|---|
| D-004 | 人工记载的世代为权威。用户**主动更正**人物世代时，后代世代按相同差值同步更正并保存；跨支、多父母、无法识别世代等冲突须失败并保留数据。普通推导和只读展示不得改写资料。 | 不得将主动更正简化成只移动当前人物；同步与冲突保护须在同一业务操作中兑现。 |
| D-026 连续编修 | 普通新增子女可在草稿中预填父母下一世，仍允许编辑为跨代；预填进入草稿，保存后才持久化。 | 草稿预填与主动更正既有人物是不同情形，不把界面临时推导当成已记录事实。 |
| D-032、D-036 | 首节点录入主世系，以房头为一世，可为第八世等；主线谱系人物均有世代，配偶不记录世代。 | 保存首节点应有主世系，不预设首节点为一世；创建空谱及取消首节点录入仍可行。 |
| D-036 普通兄弟姐妹补充 | 按目标父位置所属父亲的下一世预填；父亲第 3 世、选中子女第 6 世时预填第 4 世。 | 即使被选人物跨代也不复制其世代；生母仍按 D-035 从被选人物取，两者分别判断。 |
| D-036 配偶补充 | 配偶不记录世代，只在主线人物位置旁显示；配偶保留独立 Person 身份。 | 不将主线位置或显示列推断、复制成配偶的世代；配偶不能因主线人物须有世代而被要求填写。 |
| D-036 父子世代异常补充 | 普通子女世代与父亲相同或更早时，提示异常并阻止保存，保留输入。 | 例如父亲 5 世、子女 4 或 5 世均不得保存；子女 6 世或更晚不因该条被禁止。 |
| D-036 普通合法跨代确认补充 | 编修者明确填写晚于父亲但跨越多世的普通子女世代时直接保存，不额外确认。 | 父亲 3 世、子女 6 世按用户填写保存；不把普通合法跨代归入警告确认。其他结构性警告仍按有效契约。 |
| 人物与亲属关系领域模型 §10.1–10.4 | 显式世代可独立记录；新增关系、迁移、嗣继、祧继、拆支和重新挂接不自动覆盖；世代异常不得仅因不一致擅改历史；世代与画布层级是不同概念。 | 列举的结构操作与用户主动更正不是同一动作；现有文字未直接否定 D-004 的主动更正例外，不应静默用任一概括性表述覆盖另一方。后续可定向补充交叉引用，契约未获明确授权前不修改。 |
| 画布交互 §8、系统架构 §6、§8 | 普通编辑操作完成后自动保存，不逐字写入；Enter、失焦、明确选择或其他已确认完成事件进入统一业务 Command，失败保留草稿。 | 沿用既有完成事件与切谱保护，不新增普通录入的统一保存步骤；具体控件仍须防止提交竞争与误触发。 |
| D-026 跨代、画布交互 §9.4 | 已明确的跨代关系按人物实际世代跨列直接连接；不制造中间人物或自动改写关系、已记录世代。 | 本切片只处理普通人物及已有事实显示，不借机实现嗣继/祧继关系创建或多位置规则。 |

## 现有实现与差异

- [V1 首节点资料命令](../PuJiang.V1.Application/FirstRootApplication.cs)和[对话框](../ZupuPaiBan/Views/V1LineageDialogs.cs)支持创建或修改首节点显式世代；其[存储](../PuJiang.V1.Persistence/IsolatedFirstRootStore.cs)只比较并更新首节点，没有检查或同步后代。现有 [V1 测试](../PuJiang.Tests/V1LineageSliceTests.cs)覆盖首节点值及重试，**不覆盖后代同步**，不能作为 D-004 已满足的证据。
- [V1 人物模型](../PuJiang.Domain/Entities.cs)可存 `ExplicitGeneration`，但设置方法目前与首节点资料命名耦合；[子女投影](../PuJiang.V1.Persistence/IsolatedChildStore.cs)读取该字段，而 [PersonProfile](../PuJiang.V1.Application/PersonProfileApplication.cs)及右侧普通人物编辑目前没有世代字段或对应写入入口。
- 当前 [AddChild / AddSibling](../PuJiang.V1.Application/ChildApplication.cs) 命令均没有世代参数，[隔离存储](../PuJiang.V1.Persistence/IsolatedChildStore.cs)创建人物时未设置显式世代；现有名字草稿也未提供世代字段。直接点画布的“添加首节点”路径亦不经过主世系提示。上述是实现差异，不代表可通过默认画布列补写业务世代。
- [V1 画布](../ZupuPaiBan/Views/V1FirstRootWindow.cs)使用已记录显式世代；没有值时目前按父位置加一生成**显示用**层级，根默认显示层级零；父子世代非递增时报错。此推导不写回事实，但也不等于已完整实现契约对缺失/冲突的诊断与处理。[跨代 UI 测试](../PuJiang.Tests/V1FirstRootWindowTests.cs)通过隔离测试构造子女显式世代，验证现有事实的显示及重开，不是用户录入入口。
- 旧 [WorkbenchPersonProfileCommand](../ZupuPaiBan/Data/WorkbenchPersonProfileCommand.cs)已有同差值遍历、事务和异常检查：原世代不明且有后代时拒绝，目标/后代不明、循环、调整后越界或关系冲突也拒绝。该实现可评估复用交互和校验思路；它采用旧模型、旧图表及 `1–1000` 等历史实现细节，不能未经核对直接视为 V1 领域规则或旧数据兼容要求。

## 建议首批范围与前置条件（非批准）

1. 仅考虑当前 Lineage 内、明确普通生父关系和单位置的虚构谱系；在保留现有三栏工作台的前提下，为普通人物提供世代录入，并统一处理现有首节点编辑入口。涉及复杂多位置、跨支、嗣继/祧继及其他关系先按已确认失败保护处理，不扩展业务。
2. 将首节点录入、已记录世代的主动更正、普通子女和普通兄弟姐妹新增草稿预填及只读层级推导分别核对；**已记录值主动更正不能省略 D-004 后代同差值**。用户已确认的例外不需要重新表决；不清楚的具体边界不得自行补全。
3. 更新首节点与普通人物时采用统一 Application Command/事务，检查 Lineage、PersonId、PlacementId、原值、受影响后代及关系；失败完整回滚并保留输入，重试不得重复调整；布局和投影不能写回世代事实。具体技术实现和版本保护待批准后确定。
4. 主线世代以正整数进行输入校验；数值转换溢出或存储表达范围外提示输入无效。旧实现 `1–1000` 不自动升级为已确认业务上限；若具体产品上限影响规则，先确认。不能把显示用推导存为历史事实。

## 待确认事项

1. **正常业务不应出现无世代主线人物：** 用户澄清主线谱系人物始终有世代，即使是错的；此前将“无世代主线人物首次填写”当作正常业务分支的问题不再成立。配偶按 D-036 的明确例外不记录世代。现有测试模型及界面允许主线空值是实现差异，不能将其显示推导静默认定为已保存事实；不因此引入旧数据兼容或迁移。
2. **编辑时清空输入：** 主线人物保存后须有世代；输入草稿可暂时清空，但不能将主线人物保存为无世代。空输入提示及取消恢复的具体交互尚需设计，不据此修改后代。
3. **后代与范围：** 当前 Lineage 的“后代”在普通单位置范围容易界定；跨支、多父母、多位置、未记录世代、循环及超出有效范围按 D-004 的失败保护核对，不自行补齐缺失值。对于首批普通位置内哪些异常允许用户处理，须结合契约和用户确认。
4. **展示与切换：** 用户已明确普通子女世代不晚于父亲时提示并阻止保存；如何在画布呈现已存在异常事实、同一人物多个位置和双 ViewMode 交互仍不在首批擅自扩展。用户已确认普通合法跨代直接保存，领域契约 §15.3 已定向协调；其他结构性警告仍遵守相关契约。
5. **提交方式：** D-029 与系统架构 §8.3 已明确操作完成后自动保存及 Enter、失焦等完成事件；受影响后代如何展示及何种异常提示仍须设计，不能重新要求每次普通录入额外点击统一保存按钮。
6. **配偶人物：** 用户确认配偶不记录世代，只在主线位置旁显示；配偶保留独立 Person 身份。配偶同时成为主线位置人物等特殊身份边界尚未确认，不在本切片自行扩展。

## 最小业务流程建议（待批准）

1. 新建空谱依旧可取消首节点；选择录入首节点时填写姓名与主世系，例如第 8 世，资料在同一次业务提交保存；直接画布入口也须遵守同一规则，不产生无世代人物。取消或失败不产生半成品。
2. 从第 8 世人物新增普通子女时，草稿预填第 9 世；可按 D-026 编辑为实际跨代值，提交时连同姓名、人物、关系和位置原子保存。预览只作为草稿，不凭画布坐标写入世代。
3. 从已选普通生子位置新增兄弟姐妹，按当前父位置所属父亲世代 + 1 预填；所选人物世代即使不同也不改变此默认。D-035 的生母快照与目标父位置/世代校验独立处理，不因为世代计算改写生母。
4. 已有人物主动更正世代时，识别同谱内受影响的普通后代，按相同差值与本人同事务保存；遇 D-004 明确的跨支、多父母及世代无法识别冲突，保持原值并保留草稿。首节点原有修改入口必须纳入同一规则，不能留存绕过后代同步的写入入口。

## 异常处理与契约协调建议

| 情形 | 现有依据 | 本次收敛的处理边界 |
|---|---|---|
| 未输入、非数字、非正数或数值溢出 | D-036 主线须有世代；V1 现有首节点实现要求正整数。 | 不提交无效输入，提示原因并保留草稿；Esc 取消未提交编辑。技术表示范围之外拒绝输入，但不将旧工作台 `1000` 限额当成新业务决定。 |
| 子女明确录为跨代 | D-026 允许编辑为跨代；用户确认普通合法跨代不额外确认，领域契约 §15.3 已协调。 | 子女晚于父亲但跨越多世时，按所填写资料直接保存，不伪造中间人、不额外弹窗；其他结构性警告仍按相关规则。 |
| 主动更正遇跨支、多父母、未知世代或循环等冲突 | D-004 明确冲突须失败并保留数据；领域契约 §15.2 禁止非法循环。 | 不能只保存部分后代或默默猜测；提示无法完成及需要核实的对象，保留输入。复杂关系本切片不新增处理规则。 |
| 普通子女世代不晚于父亲 | D-036 已明确提示异常并阻止保存；当前 V1 布局也拒绝这类连线。 | 本次输入不得提交，保留草稿；已存在异常事实的具体画布呈现仍需确定，不得擅自改写历史数据或声称已有完整诊断。 |

本轮已定向协调**领域模型 §10.1–10.3、§15.3**、**画布交互 §3.1、§6.4–6.5、§7.1**、**系统架构 §5.1**及**编修操作 §4.1**，落实 D-004/D-035/D-036；并更正编修操作 §4.1 遗留的旧生母表述。保留结构操作不自动覆盖、普通新增子女生母规则、其他警告及未涉及的业务范围。

## 最小技术任务与依赖（待批准）

1. **领域及命令边界：** 区分带世系位置的主线人物与不记录世代的配偶，不对全部 Person 设置一刀切非空约束；把首节点和普通人物主动更正统一纳入同一业务规则，不能保留绕过后代同步的旧入口。
2. **创建与草稿：** 首节点保存主世系；子女及普通兄弟姐妹提交经确认的父亲下一世草稿，关联已有的父位置、生母规则和操作回执。先校验父位置和世代快照，过期保留输入，不以投影层级或自然顺序做持久化依据。
3. **后代事务与重读：** 在当前 Lineage、单位置且普通关系已明确的范围读取目标及后代，计算同差值并统一校验受影响事实、值和关系；同事务保存和回执。重复提交不重复调整，失败完全回滚；不做旧数据兼容或迁移。
4. **工作台与显示：** 沿用原有三栏、画布、输入完成提交及焦点保护；明确显示提交失败、结果待确认与刷新失败。投影读取已记录世代并复用现有跨代布局，坐标与显示层不得写业务事实。
5. **验收：** 为新隔离数据库建立根节点、两代普通后代和兄弟姐妹样本，覆盖下表；运行 Release 构建、日常测试、相关 WPF 测试，再由用户用独立虚构样本验收。顺序为 1 → 2/3 → 4 → 5，不代表用户已经批准实施。
