## 实现现状与前置缺口

- [BranchApplication](../PuJiang.V1.Application/BranchApplication.cs) 与 [IsolatedBranchStore](../PuJiang.V1.Persistence/IsolatedBranchStore.cs) 已提供拆支、删除和根父母资料操作，但没有普通挂接 Command；根父母资料输入会新建人物，不等于把现有目标父位置挂上。
- [Placement](../PuJiang.Domain/Entities.cs) 已有上级位置、排行和拆支能力；不存在可直接复用的普通挂接领域操作。现有 [排行存储](../PuJiang.V1.Persistence/IsolatedChildOrderStore.cs) 检查目标同胞顺序和版本；[世代存储](../PuJiang.V1.Persistence/IsolatedGenerationStore.cs) 有主动更正与后代同步，但用户已明确普通挂接时整支调整世代；契约和首批范围已协调，不能将现有主动更正命令直接当作已完成的挂接实现。
- 领域 §8.3 要求原生父关系保留于修改历史。应核对 V1 已有操作日志能否保存原关系身份及变更依据、失败是否同事务；目前技术操作回执只证明幂等，不能宣称已满足该历史要求。历史存储和必要保留身份的具体实现待设计，不据此扩大为完整撤销系统。
- 提交前须重新校验来源及目标、目标同胞顺序、相关人物/父母/世代和草稿上下文；并保证原子失败、重复提交及提交后重读。具体快照与事务实现留待规则确认后设计。

## 待确认事项

1. **生母细节：** 已确认新父亲第一位有效配偶为默认生母，无配偶暂不记录并按首配偶规则补录；新父亲已有首位有效配偶时，即使原先主动清空，本次也按首位配偶重新确定；新父亲无配偶时，即使原先主动清空也先暂不记录，之后新增首配偶按新父位置范围自动补录；挂接后再次主动清空等其他情形仍按 D-030 保护。排序异常和角色不一致不能猜测。
2. **世代协调：** 已确认挂接时整支调整至新父亲下一世；领域 §8.1、§8.3、§10.2 已定向协调普通生子迁移的例外，保留 D-004、D-036 未冲突部分；复杂和异常分支不纳入首批。
3. **目标排行：** 已确认追加到目标父位置对应性别组末尾，之后可调整；已有排序异常时如何处理仍须核对，不能静默猜测。
4. **交互与确认：** 用户已确认选择新父亲后先显示影响，确认后挂接；建议展示源及目标、涉及的父母、分支、世代和排行变化。具体选择入口和展示细节待核对；取消、失败、切谱和过期时保护状态，保留现有交互。
5. **历史依据与清理：** 原生父关系历史需要保存哪些信息、如何呈现、保存期限与 D-038 无业务引用清理如何协调；现有日志是否足够必须核对，不能以回执替代历史或承诺撤销。
6. **边界条件：** 目标就是原生父、原父母信息不完整、目标父角色不一致、目标属于来源后代或排序受损时，按契约校验与用户确认处理；不可据姓名、位置外观或性别默认推断身份。

## 规则收敛与定向协调记录

1. **操作与提交单位：** 普通挂接依据已选的源、目标位置执行“迁移本人及后代”，与 D-038 拆支、属性面板直接修改父母资料分别处理；本人、受承接的后代结构、人物身份及内部亲属事实作为同一分支。目标谱系、位置、父母角色及禁止循环等仍须校验。挂接与生父母变更、世代调整、目标排行及必要历史记录应原子提交，取消不写入；这是对现有事务契约的首批验收要求，不新增挂接业务规则。
2. **D-030/D-031 边界：** 新父亲第一位配偶依据当前 Lineage 的持久化顺序确定；排序缺失、损坏或引用无效且无法确定首位时，不得按坐标、自然顺序或其他线索猜测。配偶角色与生母不一致时亦不得猜测。后续首配偶补录仍有父位置与主动清空保护。用户确认新父亲已有首位有效配偶时，本次挂接即使此前主动清空，也按新父首配偶重新确定；无配偶时，即使原先主动清空也暂不记录，之后新父新增第一位配偶按新父位置范围自动补录；挂接后再次主动清空等其他情形仍按 D-030 保护。
3. **世代建议与契约冲突：** 对普通挂接，用户已明确整支调整至目标父下一世；拟按“目标父世代 + 1 − 原首节点世代”的相同差值调整承接分支主线人物，借鉴 D-004 主动更正保留相对差距的方式；用户已确认首批普通单位置分支按同一差值调整；复杂跨代、异常和历史覆盖规则未因此确定。世代无效、越界或存在无法安全确定范围的关系时，建议在写入前阻止并保留原事实，不自行裁剪或部分更改。
4. **历史依据：** 领域契约 §8.3、§9.4 要求原生父关系仅保留于修改历史并保留变更依据；[现有谱系首页日志](../PuJiang.V1.Persistence/IsolatedLineageStore.cs) 目前记录创建谱系，工作台文案表明仅覆盖谱系与首节点创建，不能证明支持挂接关系前后记录。建议首批设计可检索的最小变更依据，与挂接同事务保存、失败回滚；保存字段、展示、保留期以及历史与 D-038 自动清理如何共存仍需确定。技术回执不等于历史，不承诺撤销。
5. **定向契约修订记录：** 原领域 §8.1“保留……显式世代”、§8.3“不自动覆盖显式世代”及 §10.2 将“迁移”“重新挂接”一概列为不覆盖，已针对已确认的普通迁移明确例外：整支按新父下一世调整；拆支、嗣继、祧继及其他未确认情形维持原有约束。D-004、D-036 保留原决策及主动更正规则，记录普通挂接的范围和原因；编修、画布及系统总体架构契约均已补充与领域一致的普通挂接结果。用户已确认首批方案，四份契约已定向协调；各自未冲突规则保持。
6. **目标排行和交互：** 用户已确认目标同性别组末尾追加、随后可调整；异常顺序拒绝并保留原值可复用现有保护，但须针对挂接核对。用户已确认选定新父亲后先显示影响并确认；建议从现有画布选择来源和目标，清晰展示父母、世代和分支影响，具体入口与样式待核对。

## 已确认首批方案与任务依赖

**建议边界：** 来源限当前谱系已拆出的独立根位置，目标限同谱普通父位置；只实施用户明确选择的“迁移本人及后代”。挂接前在现有画布选择来源和目标，列出人物及分支、旧/新父母、根世代及受影响人数、目标排行；用户确认后一次保存，取消无写入。入口样式属实现细节；用户已确认影响展示与确认，但展示字段是建议。

**世代处理建议：** 对首批完整普通单位置分支，按新父世代加一与旧根世代的差值统一平移分支内各主线世代。例如新父第 3 世、原根第 8 世、后代第 9 世，调整为第 4 世和第 5 世；沿用 D-004 已确认的同差值原则。D-039 已确认整支调整为从新父下一世起，但并未单独决定复杂跨代或异常分支的计算方式：超出首批可安全识别范围、数值无效或越界时应提示并拒绝，不做部分写入。上述计算已确认为首批普通单位置场景，不改变嗣继、祧继或拆支世代规则。

**历史与清理建议：** 对被替换的原生父关系，在同一事务保存最小历史快照，例如原子女人物身份、原生父身份及当时名称、原关系身份、操作时间和新生父身份；不将旧关系继续当作当前生父事实，不按姓名合并，也不因此承诺撤销。原父人物仍有当前业务引用时保留；历史采用独立快照或其他能保留依据的形式，避免清理导致历史悬空。用户已确认最小历史依据方案；字段、可见方式和清理的具体技术处理可在契约边界内设计，不自行扩展保留策略。已有首页日志和技术回执不能代替此要求。

**最小依赖顺序：**

1. 定向修订领域 §8.1、§8.3、§10.2 中普通迁移的世代例外，并核对编修 §4.4、画布 §9.2 及系统架构；记录 D-039 与 D-004/D-036 的关系，保留未冲突条款。上述定向契约协调已完成，实施与验证仍待批准。
2. 先完成普通位置及关系合法性、世代差值、目标同性别组末尾追加和新父首配偶选择的领域／Application 设计；异常排序、失效位置或无法安全确定分支时拒绝，保留原始数据。
3. 在独立新建虚构库中实现统一事务：位置、根人物新父母事实、分支世代、排行、原生父历史和幂等回执共同提交或回滚；保留 D-030 在挂接后的主动清空保护及已确认的限定例外。
4. 复用既有三栏画布提供选源、选目标、影响预览及确认；绑定来源和目标位置与所需版本，确认后变化则拒绝过期操作，保留可恢复的上下文。
5. 执行针对性自动化、Release 构建、日常测试和独立样本重开验证；人工验收通过后再按现有约定提交推送。

**需要继续确认或复核：** 历史快照具体可见范围及与清理的技术方式；目标排行或配偶排序异常时沿用既有拒绝及修复能力是否完整；首批限制到普通单位置根分支是否能覆盖用户期待。用户已确认首批普通单位置根分支范围及最小历史依据方案；技术细节仍须设计，后续实施已获用户批准，复杂关系及生产数据库仍不包含。
