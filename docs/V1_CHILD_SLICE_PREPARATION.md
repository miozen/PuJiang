## 已确认业务规则

| 主题 | 规则 |
|---|---|
| 操作上下文 | 使用当前有效父 PlacementId，在该父位置下创建子位置；该子位置默认承接新子女后代，仍遵守单一有效承接位置及既有多位置规则。人物身份、关系事实和世系位置分别为 Person、Relationship、Placement。 |
| 生母默认 | 无配偶可先新增子女、不记录生母；唯一配偶默认该配偶，多配偶默认当前 Lineage 持久化排序第一位有效夫妻配偶；两种 ViewMode 共用该排序，不以画布坐标或数据库自然顺序确定第一位。默认直接保存为正常已确认母子关系，不增加待考确认、考证弹窗或额外普通录入步骤。 |
| 首配偶补录 | 先新增子女后新增第一位配偶时，为当前父位置范围内尚无生母且非用户主动清空的子女自动补充该配偶。新增第二位或更多配偶不覆盖已有生母。 |
| 修改和清空 | 用户可从右侧属性面板修改或清空生母；候选限定该子女生父的有效配偶，不能列出其他女性；不在候选中的已记录关系保留，允许显式更正或清空。用户主动清空的状态必须与可自动补录的未知状态区分，后续自动补充不得覆盖。不改变生父、其他子女或无关关系。 |
| 性别与排行 | 新增主线人物节点默认男性，新增配偶默认女性，用户可改；修改时校验既有父母角色一致性，并按既有规则分别重算相关位置排行；不能以新人物默认性别反推既有人物性别。实际排行与历史行第分离。 |
| 空姓名 | 用户主动添加空节点可创建空姓名真实人物及合法位置，参与关系、排行和后代承接；补名更新原 PersonId，普通姓名输入取消不创建人物。 |
| 事务与焦点 | 人物、必要关系、位置和排行原子提交；成功焦点为新 PersonId + PlacementId。失败保留输入并可重试；同操作重复提交不得重复创建；已提交但刷新失败须分开报告。 |
| 交互和隔离 | 普通流程保持选中父亲 → 添加子女 → 输入姓名；保留现有 WPF 工作台和已验收交互，使用隔离虚构数据；投影、布局和画布不作为关系事实来源。 |

已知关系不允许随意重写；生父、生母的已确认关系各最多一位，未知父母不自动造人。项目主姓氏只作为新人物默认值，人物自身保存完整姓名。显式世代不因新增关系自动覆盖；旧决策允许对普通新子女草稿预填下一世，但不授权改写已有资料。

## 已协调冲突

1. 编修 §4.1 和交互 §6.5 原先对多配偶默认生母的限制，已定向修订为使用持久化配偶排序第一位；不改写已有兄弟姐妹或其他子女的已记录生母。
2. 交互 §9.1 与总体架构 §6.4／§15.2 原先要求新增配偶不改变子女生母，已明确首位配偶对符合条件、未被主动清空的未知生母进行补录的限定例外；已记录与主动清空均受到保护。
3. 领域 §4.3 原先禁止仅据配偶推断且仅将默认作为录入辅助，现明确 D-030 的默认及首次补录为例外，并直接保存正常已确认母子关系；普通资料推断禁止仍然有效。
4. 交互 §13.1 原“不得保存无效的空姓名人物”已明确为普通姓名输入无效不能当作已命名人物提交；主动空节点仍可创建。对应 §6.2 和领域 §3.2.1 的既有规则保留。
5. D-028 中“仅创建时计算，后续婚配变化不得重算”的绝对表述，在 D-030 的首次新增配偶限定补录范围内被取代；其历史文本保留并标注后续限定。不以旧代码的 ID 顺序替代持久化排序。
6. 领域、编修、交互与架构分别补充 Placement 上下文、单一承接、事务及角色一致性要求；其他嗣继、祧继、多位置和删除规则未改变。

## 仍待明确的特殊边界

- **排序与资格：** 按 D-031 更正，配偶顺序属于当前 Lineage，横向图与吊线图共用；旧图表排序实现不直接作为 V1 权威。隔离切片遇到排序缺失或损坏、首位配偶身份或生母角色不一致时，提示并拒绝相关写入，既不猜测排序也不更改性别或关系；隔离修复入口及实际验证范围见[接力](HANDOFF.md)，真实数据接入仍未实施。
- **人物与角色：** 新建隔离样本可持久化性别；不能据“新增主线默认男性”反推旧样本或既有人物的性别。配偶默认女性；若资料被用户修改或原资料不完整，遵守 D-028 对生父母角色不确定不得猜测的限制。隔离切片在性别与已记录父母角色冲突时提示并拒绝，保留草稿和原关系；复杂角色更正流程未扩展。
- **多位置、嗣继与祧继：** 本次确认普通新增的当前位置及承接，其他位置间的共享、非承接位置操作和复杂关系仍依既有契约及 Q-01～Q-10，不自行扩展。何种子女属于首配偶补录的“当前父位置范围”，应在这些既有规则下明确可核验的边界。
- **世代、房支与历史：** 父世代缺失、预填何时成为显式事实、房支继承细节（Q-06）及不完整旧记录的排行（Q-07）尚需明确；不修改既有记录来消除差异。
- **并发和状态表示：** 用户主动清空必须可区分且能在重开、失败回滚和并发操作后保留；具体字段、版本冲突与命令参数属于实施设计，不在本轮假定。补录与人物、婚配及关系的事务边界应保证一次业务操作的原子性。
- **空节点入口：** 主动空姓名真实人物已确认；带当前父位置新增空姓名子女的入口形式和交互细节仍需按既有六类命令设计，不能把普通取消当作空节点。

## 实施顺序

先定义能够表达真实人物性别、关系、位置挂接、承接、位置排行、持久化配偶排序与主动清空状态的最小领域边界，再按明确的优先范围接通 Application Command、隔离事务、投影与现有隔离画布。可先验无配偶单方路径，但该分步建议不能将唯一／多配偶及首次配偶补录从已确认需求中移除。测试样本应显式给父亲角色，不得把缺失性别的既有人物默认为男性。复杂多位置、嗣继、祧继在其规则未明确前不扩展；不重写旧工作台。

## 验收矩阵

| 场景 | 必须验证 |
|---|---|
| 无配偶新增 | 当前有效父 PersonId + PlacementId 下新增一个子女和子位置；有明确父子事实，母亲缺失且不补造人物。 |
| 唯一及多配偶新增 | 唯一配偶或持久化顺序首位成为正常生母关系；不使用坐标、数据库自然顺序，不增加考证确认；原有生母不变。 |
| 先子女后首配偶 | 仅当前父位置范围内符合条件的无母子女补录首配偶；有母、已主动清空或范围外子女不被修改；第二及后续配偶不覆盖。 |
| 主动清空 | 用户修改或清空生母不影响生父、其他子女或后代；主动清空状态跨重开保持，不被后续自动补充。 |
| 独立身份与承接 | 新 PersonId 与 PlacementId 稳定、独立；当前父位置和新子位置的结构及后代承接符合规则；不同位置不互相改写。 |
| 性别与排行 | 主线新人物默认男性、配偶默认女性且可更改；每个相关位置的性别分组与排行按规则更新；历史行第和关系事实不被隐式重写，父母角色一致性得到校验。 |
| 空姓名与取消 | 主动空节点创建真实人物及位置；普通姓名输入取消零写入；后续补名保持 PersonId、PlacementId 和关系。 |
| 事务与并发 | 人物、必要关系、位置、排行及受影响补录任一失败时按业务操作整体回滚；重复提交不重复创建，过期目标或排序不静默覆盖。 |
| 投影、布局与工作台 | 保存后生成对应节点和边；成功焦点为新 PersonId + PlacementId，右侧资料同步；Enter／空白提交、取消、失败保留和保存后刷新失败分别验证。 |
| 重开及环境 | 关闭连接重读后事实、位置、排行、排序和主动清空状态完整；只使用独立虚构数据库，保留旧工作台及已有测试。 |

本轮只修订文档，未实现或运行本切片测试；实际实现和验收须另获批准。
