# V1 隔离虚构样本跨应用重开：准备

状态：用户已批准实施；实际进度、验证和未完成事项见[接力](HANDOFF.md)。仅用于独立虚构样本；保留现有工作台。普通切谱继续在应用内完成，不要求退出应用。项目全程不做旧数据兼容、迁移或转换，见 [D-033](DECISIONS.md#d-033--新项目不需要旧数据兼容)。

## 已确认范围与现状

- 用户确认：进入“V1 隔离样本”时默认打开上次使用的虚构样本，同时保留新建入口；随后另行批准实施。
- [D-029](DECISIONS.md#d-029--v10-领域架构与自动保存)的自动保存与失败保留草稿仍有效；[D-032](DECISIONS.md#d-032--v1-独立谱系创建与切换交互方向)的应用内切谱不需要退出应用。本切片的退出重开是额外的样本持久性验收，不改变切谱流程。
- `IsolatedTestDatabase.CreateNew()` 仅在系统临时目录下创建随机 SQLite 文件，私有构造器不接受外部调用者传入路径；`IsolatedSample.CreateAsync()` 每次新建库并初始化项目和谱系。`MainWindow` 在进程内缓存样本，退出后不会恢复。现有文件库重读测试并不等于应用跨进程重开。
- `AppDataPaths` 在明确设置 `PUJIANG_TEST_DATA_ROOT` 时校验绝对路径及与默认正式目录的路径重叠；未设置时回落正式目录。V1 的临时库另用 `Path.GetTempPath()`，两者并非同一隔离保证，现有检查也不能直接证明所有链接路径安全。

## 最小方案

1. 仅在显式配置的独立测试根目录下启用可重开虚构样本；固定专用子目录，例如 `<独立测试根>/V1FictionalSamples/`，不得从正式目录回退、扫描或打开任意路径。启动验收时将 `PUJIANG_TEST_DATA_ROOT`、`TEMP`、`TMP` 都指向专用测试范围；未配置、空值、相对路径或与正式目录重叠时拒绝进入此持久样本流程。路径需检查目录及目标的链接／重解析点，防止绕出受控范围；具体实现须覆盖 Windows 路径行为。
2. 样本使用新生成的稳定样本 ID 和专用标记／版本，注册表仅保存受控 ID 与最近使用指针，数据库路径由程序在受控目录内构造；不提供任意数据库文件选择。打开前先检查标记、版本、目标文件及其项目身份一致性；标记只能辅助识别，不能单独证明文件安全。样本中的业务事实仍以其数据库为权威，不因注册表另建业务副本。
3. 用户主动进入“V1 隔离样本”时打开上次成功使用的样本；首次无记录时提供新建。新建产生新 ID、新文件及虚构初始化数据，不覆盖已有样本；完成初始化后才更新最近使用指针。入口明确标注虚构隔离样本。样本内谱系切换和现有草稿保护沿用既有行为。
4. 已有样本用受控入口打开存在的文件，不以 `EnsureCreated` 或自动迁移修复它；只有新建流程初始化新库。读取项目与谱系数据后接入现有投影及工作台，不把重开误作全新建谱。是否恢复上次选中谱系或焦点属于视图状态，首批不作为已确认业务规则；可先展示现有谱系列表供用户选择。
5. 关闭窗口或退出时沿用现有未提交草稿提示及失败保护；已提交数据应在正常结束后重读。未提交草稿不承诺跨进程恢复；禁止将失败写入报告为成功。旧临时样本不自动发现、升级、复制或删除。

## 失败保护

最近样本缺失、损坏、版本不支持、标记或身份不匹配、路径异常或文件被占用时，说明原因并停止打开；保留原文件和原最近记录，不静默新建、覆盖、修复或回退正式数据。用户可显式选择新建独立样本；新建失败不得替换最近成功样本或留下可误认为成功的注册记录。真实文件系统与 SQLite 的中断窗口需要实现时设计可验证的初始化发布顺序，不以两次独立写入宣称原子。

工作台提交失败保留当前输入并提示；重开后已提交事实以实际数据库结果为准。注册表或指针写入失败时不得破坏已有样本；若新样本已创建但尚未登记，须明确提示并保留文件，不自动清理或覆盖。异常后的恢复或修复工具不在首批范围。

## 原任务拆分及验收矩阵

此表保留准备时的验收计划；实际执行范围、用户反馈和未覆盖事项以[接力](HANDOFF.md)为准。

| 顺序 | 任务及依赖 | 验收标准 |
| --- | --- | --- |
| 1 | 受控根目录与样本身份；先于持久化入口 | 显式隔离配置成功；无配置、正式目录重叠、越界或链接路径拒绝，不触碰真实库。 |
| 2 | 新建与最近样本登记，依赖 1 | 初始化成功才登记；新建生成独立 ID，不覆盖上一个；登记或初始化失败有明确提示并保留原数据。 |
| 3 | 受控打开与只读重建上下文，依赖 1、2 | 关闭整个应用后重新启动并进入入口，打开同一 ID 的样本；项目、谱系、人物、关系、位置及排序从库重读，不自动初始化新库。 |
| 4 | 现有工作台接入，依赖 3 | 两个独立谱系的首页及画布可用；应用内切谱无需退出；既有自动保存与草稿失败保护有效。 |
| 5 | 异常和实际验收，依赖 2–4 | 缺文件、标记不符、损坏、不可访问或版本不支持时拒绝且不改原文件，不悄悄换新样本；修正后可重试。 |
| 6 | 回归与用户操作，依赖 1–5 | 使用独立虚构目录实际建立两个谱系及人物、配偶顺序、子女排行；正常退出、重启、重读核对身份与事实，再次切谱并完成可操作验收。运行 Release 构建、相关专项及完整日常测试，报告结果和未执行项。 |

测试仅使用新建虚构目录与样本；不访问、迁移真实数据库，不运行旧数据转换，不纳入复杂关系、完整图表管理或正式数据恢复。关闭重开验收不等于异常断电恢复保证。
