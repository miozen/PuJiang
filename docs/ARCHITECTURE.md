# 架构契约

## 产品与技术边界

谱匠（PuJiang）的目标是完全离线的 Windows 单机族谱管理系统，不是仅用于排版的工具。技术基线由 [D-001](DECISIONS.md#d-001--产品与技术基线) 约束：.NET 10、WPF、EF Core、SQLite；不依赖云端或服务器。源码目录与命名空间仍为 `ZupuPaiBan`，属于后续专项渐进重命名范围，见 [D-009](DECISIONS.md#d-009--项目名称仓库与分支策略)。

## Current：源码已实现

- `PuJiang.slnx` 统一入口包含一个 `net10.0-windows` WPF 项目和 `PuJiang.Tests` xUnit 项目；`global.json` 固定 SDK `10.0.402`。依赖 CommunityToolkit.Mvvm、EF Core SQLite、ClosedXML、PdfSharpCore。
- 界面位于 `Views/` 与 `MainWindow.xaml`；ViewModel 位于 `ViewModels/`；数据访问位于 `Data/`；布局、打印与交换位于 `Services/`。
- 旧成员树及其操作仍以 `FamilyMember`（可空 `FatherId`、字符串 `SpouseName`、代数、排行）为界面数据模型。WPF 另提供目标模型族谱的创建、会话内选择、按谱人物列表、姓名及基础档案编辑、无关系人物的确认删除，以及生物子女事务新增、已有子女关联、列表和指定生物父母关系的确认解除。有关联关系或婚配记录的人物不可通过此入口删除；解除会删除该关系记录（含备注和来源），但保留人物及其他关系；重新关联建立新关系，不能恢复旧备注和来源。其他人物档案编辑、复杂删除和关系管理尚未切换；这不表示 P1 管理功能已完成。
- 启动路径在现有 SQLite 库有待执行迁移时先使用 SQLite 在线备份生成并校验数据库快照，再调用 `MigrateAsync`；备份失败则终止启动。数据库专用版本化离线包创建和只读校验复用在线快照，文件菜单提供操作界面；附件、配置和恢复尚未实现。`Infrastructure/AppDataPaths.cs` 默认使用 `%LOCALAPPDATA%\\PuJiang`，支持显式独立测试数据根目录，详见 [运行规范](OPERATIONS.md#数据与日志目录)。`FileAppLogger` 提供本地轮转日志与未处理异常记录。
- 数据库备份恢复预检服务在隔离副本执行 SQLite 完整性及外键检查，并严格比对当前程序的迁移集合和同版本迁移生成的结构；备份界面可运行预检并报告覆盖范围，不替换数据库，也不证明数据的业务正确性或来源真实性。校验和正确但含外键违规、迁移差异或结构差异的包均拒绝；失败和成功预检都不改写活动数据库或原备份包，并清理其隔离副本。
- 应用创建主窗口前独占数据目录内的锁文件，并持有至进程退出，阻止支持此协议的其他谱匠实例同时使用该目录；不阻止旧版程序或其他软件直接访问数据库。
- `GenealogyDataService.GetGraphSnapshotAsync` 在读取事务中按单谱提取不可变人物、类型化关系、婚配与房支数据，保留原始记录与来源；它不选择展示主线，也尚未完成大规模性能验收。
- 目标谱系已接入基于快照的关系清单：每个人物作为独立入口，展开显示已记录关系，多条父母关系明确标注未自动选择主线，未知上系不推断为始祖；选择人物节点按 ID 接入现有目标人物档案和生物子女选择，右键可新增生物子女，双击可编辑姓名和基础档案；目标谱系区域另提供作用于当前目标人物的快捷编辑和新增子女按钮。档案通过按谱及人物 ID 限定的单条更新原子写入。关系详情只读；这不是世代层级树，旧版工具栏仍独立。相关变更后会刷新清单。
- `ZupuDbContextFactory` 提供不执行创建或迁移的 EF Core 设计时上下文；`dotnet-tools.json` 固定本地 `dotnet-ef` 10.0.12。
- `PuJiang.Tests` 使用每测试独立临时 SQLite 文件（默认禁用连接池，专项测试会显式启用并清理）；覆盖迁移、关系与事务、目标模型、备份预检、恢复隔离原型及布局样本。测试分类为 Unit、Integration、Layout、Performance 和独立进程 UI；尚无完整的人工视觉验收自动化。
- 有基础成员树、横向/左至右树布局、预览、打印、PDF/XPS 及 Excel/GEDCOM/JSON 入口。它们是原型能力，不代表正式数据交换、排版或大规模性能已验收。

旧成员树模型不支持多族谱隔离、母系、正式配偶关系、多次婚配、过继/嗣继、房支、失考或关系主线选择。详见 [D-002](DECISIONS.md#d-002--多族谱隔离) 至 [D-007](DECISIONS.md#d-007--重建范围与架构尺度)。

## Target：已确认目标架构

### 模块职责

保持一个 Windows 桌面应用，按职责形成清晰边界，而非拆分为微服务：

- **Presentation**：WPF Views/ViewModels，只负责交互、状态和导航。
- **Application**：用例编排、事务边界、导入预检、校验调用和 DTO/视图投影。
- **Domain**：人物、关系、谱系规则、世代/排行推导与校验，不依赖 WPF。
- **Infrastructure**：EF Core/SQLite、文件系统、备份、JSON/Excel/GEDCOM、打印/PDF。
- **Rendering**：从只读谱系投影生成布局和页面模型；世系图、吊线图与输出渲染器各自独立。

初期可仍在单一项目内以目录和接口边界落地；仅在编译、测试或发布收益明确时再拆工程。

### Target：数据与关系边界

- `Genealogy` 是稳定根实体。任何族谱内人物、关系、房支、导入批次、设置和备份元数据都以 `GenealogyId` 隔离。
- `Person` 保存人物档案及资料完整度；未知或信息不完整的历史记录合法。
- 父母、子女、婚配、收养、嗣继、失考等以类型化关系/家庭记录表达，保留生物关系与法理/谱载关系及来源。不得再用配偶姓名字符串承载关系。完整双人 `FamilyUnion` 是无向配对，领域层以两方稳定 ID 的规范顺序去重；反向重复在预检或写入前拒绝，单方资料不完整的记录不重排。
- 房支独立于人物与关系；世代和排行分别保存谱载原始值、推导参考值及来源/确认状态。展示主线是查询投影规则，不能改写原始关系。
- 数据库层负责外键、跨谱保护、必要唯一性；领域层负责循环、关系冲突、世代一致性和业务校验。关系与婚配的领域预校验只提供早期反馈；独立上下文在陈旧视图下同时通过预校验时，SQLite 的复合唯一索引仍是第二次提交的最终屏障，因而不会产生重复记录。`DeleteUnrelatedPersonAsync` 以单条带关系/婚配不存在条件的删除实现原子保护：删除先完成会令陈旧写入被复合外键拒绝，写入先完成则删除返回拒绝；两种顺序均不产生悬挂引用。

### Target：图、排版与输出边界

- **交互式世系图**：面对查询投影，支持逐代展开/折叠、搜索定位、路径高亮和大规模按需渲染。
- **人物管理入口**：按 [D-011](DECISIONS.md#d-011--成员树优先的操作体验) 逐步接入成员树的右键、双击和工具栏；现有目标模型列表为过渡验证界面。当前工具栏可在所选目标人物上显式新增关系或婚配：两种模态框只接收当前 `GenealogyId` 的人物快照、排除主体自身，并在提交时由 ViewModel 再次验证当前选择与对方候选范围，随后交给领域校验和数据库复合外键。关系或婚配绝不自动创建彼此、合并人物、删除或覆盖既有记录；上系失考关系显式不选对方。解除入口只列出当前人物参与的记录；用户须选择精确记录并逐项勾选确认。关系或婚配解除各以带族谱、记录 ID 和参与者条件的单条 SQL `DELETE` 提交，零行、跨谱、陈旧记录或底层失败均失败关闭，不删除人物或另一类图记录。隔离 SQLite 和 STA WPF 子进程均验证候选隔离、确认门槛与不误删其它记录；后者还在婚配新增及关系解除的 SQL 已进入执行、尚未完成时请求真实主窗口正常关闭，验证排空拒绝新操作、保留目录锁并等待既有写入以完整的单一结果结束。另有隔离 SQLite 在档案更新、关系新增、婚配新增及婚配解除的 SQL 已暂停后切换族谱：原事务以发起时已校验的族谱和人物 ID 完成，版本检查不将旧谱结果回填到新谱视图。成员树档案、右键新增子女、已有子女关联和生物父子解除亦在同样的跨谱暂停写入场景中验证。选择及写后树刷新所需图快照若遇到短暂 SQLite `BUSY`/`LOCKED`，以新的短生命周期上下文最多重试三次（25/50/75ms）；重试耗尽则清空已失效的树并按实际已提交操作显示刷新失败，绝不把已提交写入误报为回滚或执行自动合并。成员树档案、创建子女、关联已有子女及解除父子关系的底层写入失败保留原数据库图和当前内存树/选择；成员树父子与目标人物关系/婚配的新增及解除已提交但刷新失败时，数据库图仍可在解除故障后通过重新选择加载，且成功状态不会覆盖已报告的刷新失败。
- **传统吊线图**：独立布局引擎、独立页面切分；其地域谱式和复杂关系图例仍为 Proposed，见 [D-008](DECISIONS.md#d-008--传统吊线图细则)。
- **解除确认的陈旧选择：** 候选携带读取时的族谱、参与者及族谱和人物选择版本。确认前切谱或切换人物（即使再切回）会拒绝该候选；若同一记录已由外部解除，作用域删除影响零行并报告过期，重新读取当前图；刷新失败时清空树并报告，选择变化后不回填旧状态。隔离 SQLite 覆盖关系和婚配，隔离 STA WPF 测试构造确认控件验证外部解除和跨谱情形；该测试不显示模态框或验证人工点击。
- **解除确认的陈旧记录：** 候选保留完整关系或婚配不可变快照、显示的双方姓名及同一 SQLite 读取事务内的全库代数；确认框主体和列表均取自同一次快照。单条 SQL 删除同时比较族谱、参与者、记录字段、存在人物姓名、代数和代数表/触发器定义；不匹配则零行失败并重新加载人物列表和关系树，刷新失败则清空失效视图。隔离 SQLite 验证字段变化、记录和姓名 ABA、删除重插、代数损坏及触发器篡改；另验证独立进程改名 ABA 与同一读取事务，隔离 WPF 控件测试不显示窗口。
- **ABA 保护评估（历史测试原型）：** 隔离测试曾确认关系/婚配记录或姓名经两个独立提交从 A 改为 B 再改回 A 后，旧确认仍可执行。测试专用全库代数表及 `People`、`PersonRelationships`、`FamilyUnions` 的 INSERT/UPDATE/DELETE 触发器，在普通外部 SQL 写入、记录删除重插和事务回滚场景中能检测已提交变化；原型用单条条件删除比较代数，同时证明无关人物修改也会使候选过期。原型本身未接入候选、界面、生产 Migration 或恢复。可进一步研究按谱或按记录代数与墓碑/世代标识，需保留删除重插保护并验证跨谱变更、级联、触发器递归、溢出和回滚。当前预检比对 `sqlite_master` 的表、索引和触发器结构及迁移集合，新增结构会影响版本兼容。目录锁不约束第三方；有权限删除触发器、篡改代数或替换数据库的程序不能被该机制防护，数据库替换后的代数回退也不能用于保护旧候选。仅应用层版本字段要求所有写入方配合，不足以覆盖普通外部 SQL；长时间持锁跨确认会影响并发和正常退出。正式接入见下方，恢复继续关闭。
- **ABA 迁移隔离验证（测试原型，未接入）：** 在当前旧结构的隔离库先生成 SQLite 快照，再以测试专用事务安装代数表和九个触发器；安装故障回滚 DDL，旧数据和迁移前快照可读。条件删除原型核对代数类型、范围及九个触发器的名称和完整 SQL；缺失、负数、非整数、溢出、触发器缺失或同名替换时拒绝，缺失/损坏代数也使常规写入事务中止。隔离连接的真实写锁竞争、外部 ABA 及删除重插均保留旧候选不得删除；新代数可执行。旧版实际备份预检接受旧包并拒绝原型结构，活动库和包字节保持不变；另一个测试专用备份检查只验证包校验和、代数和触发器，能接受有效原型包并拒绝缺失/损坏代数和替换触发器，未组合生产预检的完整性、外键、迁移和结构检查，也未验证预检与使用间替换。此为测试 SQL 设计，不是正式 EF Migration、应用接入或生产 ABA 修复；精确 SQL 比较、全库粒度、SQLite 表重建、性能、跨进程和恶意篡改代数的限制仍须处理。
- **ABA 正式接入：** `20261030000100_AddUnlinkGeneration` 以 EF Migration 创建代数表及三类图数据的九个触发器；常规外部 SQL 的已提交写入递增代数，缺失/无效/溢出代数使触发器中止。候选读取与图快照使用同一事务，解除以单条 SQL 校验代数和版本化的精确 schema，生产备份预检除原有检查外校验代数。隔离验证旧库迁移前快照、新备份通过及旧版备份按现有严格迁移策略拒绝、独立进程 ABA、损坏失败关闭、显式降级再升级重装触发器；模拟 SQLite 重建人物表丢失触发器后读取失败关闭，未来涉及表重建的迁移必须显式重建触发器。全库代数可能使无关谱系的旧确认过期；不保证防范有权限篡改代数、修改数据库文件或替换数据库的第三方，恢复仍关闭。历史测试原型见上一段，不等同于生产实现。
- **ABA 代数与导入/退出验证：** 隔离 GEDCOM 导入 50 人和一条婚配成功时，图数据、来源记录及 51 次代数增长共同提交，原谱旧候选保守失效；婚配写入失败时图数据、来源及代数一并回滚，原候选仍可使用。另一既有族谱人物更新在提交时使旧候选失效，回滚则不失效。隔离 WPF 子进程验证外部导入及关系/婚配写入在途退出时最终代数与提交一致。250 人虚构 GEDCOM 的本机预热后各 3 次样本，以仅在隔离基准库移除人物插入触发器作为对照：关闭中位数 74.8 ms、开启 104.7 ms；包含预检与写入，样本较小且非正式性能验收，不能据此推广为普遍开销。
- **全库代数成本评估（单机隔离样本）：** 解除 SQL 暂停执行期间，另一谱人物修改提交会使关系或婚配的旧候选拒绝；回滚则不失效，两种路径的代数及图数据保持事务一致。这是可重复的保守误失效，并非实际使用频率统计。千人虚构图中，对同一 EF `SaveChangesAsync` 一次保存 999 条关系和 500 条婚配，隔离对照库仅移除相应两个 INSERT 触发器；预热、交替顺序后每轮两组各 3 次，两轮中位数分别为关闭 92.4/119.9 ms、开启 241.8/243.2 ms。该微基准不含领域校验、导入解析和人物创建，不是完整应用性能验收，不能证明细粒度代数会更快。建议先设计并在隔离库验证按 `GenealogyId` 的代数方案以减少跨谱误失效，保持现有全库实现直到验证完毕：须覆盖代数行缺失/损坏、外部 SQL、跨谱移动时旧/新谱、级联删除、同 ID 删除重插、回滚、读写原子性、迁移/备份和触发器重建，并比较写入与读取成本；涉及恶意篡改或数据库替换仍不受保护。本建议不是已实施方案或对已确认业务决策的修改。
- **按谱代数隔离原型（未接入生产）：** 测试专用表按族谱保留代数及删除后的墓碑；三类图记录变更更新对应谱，跨谱移动同时更新旧谱和新谱。隔离测试覆盖外谱写入不使原谱候选失效、同谱记录/姓名 ABA、删除重插、族谱同 ID 重建、缺失/损坏/溢出及触发器缺失/替换、跨谱移动与回滚。测试专用事务安装验证旧库快照和安装失败回滚；独立进程改名 ABA、无关系人物随族谱级联删除及同一读事务中的并发写入均已验证。包含关系、婚配及两级房支的图直接删除被外键 RESTRICT 阻止；测试仅按依赖顺序删除并在事务中提交或回滚，验证图数据、两个谱代数及全库代数一致，并不代表应用已提供删除族谱入口。测试专用完整预检组合包校验、SQLite 完整性和外键、迁移集合、参考库完整结构、全库与按谱代数检查；有效包通过，外键、迁移、触发器及缺失代数故障拒绝，活动库和包不变。参考库就绪、候选目录建立、快照复制完成和候选只读连接打开四处注入异常后，测试拥有的临时目录均被清除，源库和备份包不变；未模拟清理本身失败或进程被终止。此测试实现并非生产预检，现有生产预检仍拒绝原型结构。单机千人虚构图插入 999 条关系和 500 条婚配，预热后各三次中位数全库 250.6 ms、按谱 302.3 ms；单连接小图代数守卫各 100 次读取的三次中位数分别为 24.5 ms 和 35.0 ms。两者都是本机微基准，不代表完整图读取或普遍性能。
- **按谱方案评估：** 原型可减少跨谱无关写入造成的保守失效，但当前无实际误失效率数据，微基准也未显示性能优势。值得继续形成正式设计与验收清单，暂不切换生产：需明确墓碑生命周期、旧库 Migration 和备份兼容策略、表重建与触发器验证、批量导入及 WPF 候选/退出集成，并覆盖更多数据规模、异常清理和外部写入；不能防护恶意篡改代数或替换数据库。现有生产全库代数继续生效，自动合并及生产恢复关闭。
- **按谱正式接入设计草案（未实施）：**
  - **迁移与共存：** 继续保留生产全库代数及其触发器。待正式方案完成验证后，以新的 EF Migration 在单一事务创建按谱表、为现存族谱初始化代数并安装全部版本化触发器；启动前按现有流程完成迁移前快照，安装、初始化或结构校验失败则迁移失败关闭，不进入按谱候选操作。普通外部 SQL 的三类图记录写入递增所属谱；跨谱移动须同时递增旧谱、新谱。受保护表重建时显式重建并校验触发器。旧版应用仍可能绕过目录锁或改变结构，迁移和切换不得假定其已排空；需明确并测试共存边界，禁止把数据库替换后的旧候选当成有效候选。
  - **墓碑与溢出：** 按谱代数行无指向族谱的级联外键；删除族谱时保留并递增墓碑，同 ID 重建须继续递增而非归零，相关图变更与代数在同一事务提交或回滚。当前建议无限期保留墓碑，不做自动垃圾回收；缺失、非整数、负数、溢出或结构不可信时读取与写入失败关闭，不静默重置或重建。恶意修改代数、删除触发器后再恢复以及替换数据库不在保护范围。
  - **候选与备份：** 若未来切换，候选图、显示内容及对应谱代数须在同一读取事务获取；单条作用域删除同时验证候选字段、代数和版本化结构。生产仍保留全库校验直到按谱方案完整通过验收，不能同时依赖全库值判断候选过期来声称消除了跨谱误失效。现行备份预检严格匹配迁移集合和结构：新版本按此规则拒绝旧结构包，旧版本也拒绝新增结构包；不自动迁移或替换原备份。若未来引入旧备份转换，应作为独立隔离副本流程设计并验证，不能理解为当前支持生产恢复。
  - **接入验收门槛：** 隔离测试覆盖旧库迁移前快照及失败回滚、双版本备份预检、结构损坏/重建、墓碑删除重插与溢出、同谱和跨谱 ABA 与并发、失败关闭、来源及图数据原子性、WPF 确认/切谱/退出协调、读取与写入性能，以及正常和失败清理。还须明确可执行的退出及外部连接边界并评审；达成前不修改生产解除策略。
  - **迁移写入共存验收：** 外部写入若先取得 SQLite 写锁，按谱安装必须等待其提交或以锁错误失败关闭，不得暴露半装配结构；该已提交写入构成按谱代数初始化基线，不能被误记为迁移后的变更。安装事务先取得结构写锁时，旧模型写入必须等待安装提交，随后由新触发器递增对应谱代数。安装中断后旧结构、旧写入路径和现有全库代数保持可用；表重建导致触发器消失时，候选读取与解除必须拒绝，正式 Migration 必须显式重建并验证触发器。上述规则仅是接入门槛，未改变当前生产全库策略。
  - **正式 Migration 实现清单（未实施）：** (1) 新 Migration 先沿用启动路径的迁移前快照，在一个 SQLite 事务内创建独立、无级联外键的按谱代数/墓碑表，为现有族谱写入基线行，并在所有受保护表结构最终确定后安装版本化 `Genealogies`、`People`、`PersonRelationships` 和 `FamilyUnions` 触发器；安装、初始化、触发器定义比对或锁获取失败时整体回滚并停止启动。(2) 在候选读取/解除正式切换前，保留现有全库代数及其触发器和删除条件；旧应用只要不修改结构，仍可写入既有表并由数据库触发器同时维护按谱代数，未知外部结构变更一律不受支持。(3) 任一重建受保护表的 Migration 必须在同一 Migration 末尾重装其全库和按谱触发器；启动和候选读取均检查版本化精确定义，缺失或替换即失败关闭，不自动修补运行中数据库。(4) 备份预检继续以迁移集合和完整 schema 严格相等为准：新程序拒绝旧结构包，旧程序拒绝新结构包；不在预检或恢复中迁移、转换或替换包。(5) 接入前在隔离 SQLite 验收旧写入先提交/安装先持锁/安装中断、触发器丢失与重建、跨谱移动和墓碑、旧新双向备份拒绝、导入原子性及候选/退出竞争；全部通过后才允许独立评审候选路径是否从全库代数切换。
  - **实现前设计评审结论（有条件准入）：** 上述隔离原型已经覆盖锁顺序、旧模型已打开连接后的写入、安装中断回滚、受保护表重建后的双触发器重装、双向备份拒绝及导入原子性，足以进入正式 Migration 的设计评审；这不是实施、候选路径切换或生产恢复批准。评审必须先固定 V1 表/墓碑/触发器名称及不可变 SQL、`Up`/`Down` 顺序和 `BUSY`/`LOCKED` 的启动错误报告；再以真实 EF Migration、模型快照及生产备份预检替换测试专用安装器，并验证重建 Migration 统一生成两套触发器。本轮与前轮原型测试的 Windows CI 仍须在下一个代码检查点或用户请求时核实。
  - **V1 实现设计（未部署）：** 已固定按谱活动代数/墓碑表、11 个版本化触发器、`Up`/`Down` 的事务顺序、15 秒锁等待与失败报告，以及 SQLite 重建受保护表时的双轨触发器重装规则；完整不可变 SQL 契约、旧版共存边界与真实 Migration 验收见[按谱解除代数 V1 实现设计](SCOPED_UNLINK_GENERATION_V1_DESIGN.md)。该设计不改变当前全库候选路径、自动合并或生产恢复状态。
  - **本轮隔离导入验证：** 使用真实 GEDCOM 导入 50 个虚构人物及一条婚配；成功时新谱、来源和 51 次按谱/全库增长共同提交，已有两谱按谱值不变。来源插入和婚配插入注入失败、导入中的按谱溢出及预检后文件变更均保持失败关闭，新谱、图、来源和代数行零残留；旧谱候选仍可按测试原型解除。此为测试专用触发器与解除语句，不表示生产已采用按谱候选。
- **打印/PDF/图片**：共享“布局结果 → 页面模型”的中间层；各输出器只负责渲染，不能各自重新解释谱系关系。

### Target：持久化、安全与演进

- 使用 EF Core Migration 管理模式升级；应用启动不得以 `EnsureCreated` 承担生产升级。
- 所有导入、复杂关系变更和恢复在明确事务边界内执行；先预检，再应用，并产生可读报告。
- 备份是版本化离线包；恢复应在独立副本验证后替换目标，保留失败诊断。
- **数据库恢复实施方案（待实现和验证）：** 必须在用户明确确认数据库将整体替换及附件、配置不包含后执行；先对固定的备份内容做已验收预检，防止预检与使用之间的文件替换。持有数据目录锁并阻止新业务操作；完整关闭并释放所有 EF/SQLite 上下文、连接及连接池后进入独立恢复阶段。现有应用级排空尚不足以证明恢复安全，不能直接在运行中的 UI 替换。
- 在独占和连接关闭条件下，对当前库进行 WAL 检查及安全收敛，无法确认其他连接或日志状态时停止；不删除未知 WAL/SHM 文件。创建并校验恢复前 SQLite 一致性备份，保留备份路径；在目标库同一卷准备并验证新库，禁止覆盖现有准备文件。预检或备份失败时不替换目标。
- 替换采用经过目标 Windows 文件系统验证的同卷原子替换，同时保留原文件及恢复前快照；替换后重新打开隔离连接检查。发生失败时保留诊断与可恢复副本，验证后尝试回滚，回滚失败必须停止并报告所有路径，不自动清理。锁在恢复阶段保持持有，任何未知并发写入或文件状态都应停止；锁无法约束旧版或第三方进程。
- 替换前后须持久记录恢复阶段及文件路径，设计进程异常终止后的启动检测和人工可理解的恢复选择；不能凭一次 `File.Replace` 声称断电安全。恢复完成或失败后先结束恢复阶段、释放连接并重新启动应用，再重新加载数据；不沿用旧 UI 内存状态。该方案尚未接入生产代码，文件锁、WAL、持久记录、故障注入与进程中断恢复仍须测试。
- 测试工程中的 `IsolatedRestorePrototype` 仅用于验证锁、固定包预检、恢复前快照、同卷替换及故障注入回滚；连接停止和替换后检查由测试替身模拟，对已有 WAL/SHM 保守停止。它不属于应用，也不具备崩溃恢复、真实连接关闭或第三方写入防护能力。
- 独立 Windows 测试表明：清除连接池不会关闭正在使用的连接；WAL 读取事务可阻塞完整检查点，结束读取后检查点可完成；指定外部进程独占句柄和活跃 DELETE 模式读取连接会阻止测试原型的恢复操作。这些结果不证明能检测所有外部访问或安全关闭应用全部连接。
- 测试工程的 `RestoreJournalPrototype` 已接入测试专用恢复协调器：替换待执行记录视为不确定，未完成记录写入、损坏或缺失记录与残留文件均要求人工检查，不自动替换或删除。测试工作进程只接受临时测试根目录，实测记录写入和替换的指定边界被终止；这不等同于断电或生产恢复协调器中断验证。
- 测试工程进一步组合验证活跃 WAL 读取事务、由测试回调关闭真实 SQLite 连接和清理连接池、阶段记录与失败回滚；指定 Windows 场景中，待替换记录写入后新打开的 DELETE 模式读取连接阻止替换并保留不确定记录。这不构成对实际应用所有连接或第三方进程的关闭、阻止写入保证。
- **当前连接生命周期：** 主窗口、目标模型、旧模型成员访问、预览及协作导入共用一个协调器；旧 `DataService` 不再持有长期 `DbContext`，每次读写创建并释放登记上下文。启动迁移和备份创建的外层操作在协调器中登记，其独立 SQLite 快照连接禁用池化并在操作内释放。备份预检只操作隔离临时副本；设计时工厂属于独立工具入口。共享协调器的 SQLite 连接禁用池化。尚未将排空接入实际恢复流程，也无法约束其他进程或绕过入口。
- **停用方案（测试原型，待接入）：** 由唯一应用级协调者先原子拒绝新业务操作、等待已登记的外层操作结束，再逐个关闭已登记长期持有者及其上下文、关闭相应连接并清理对应池；嵌套调用应复用外层许可，避免排空时等待自身。所有目标模型、旧模型、预览、导入、备份及启动路径均需纳入或明确隔离，不能只依赖 UI 禁用；关闭失败、超时或取消保持失败状态，禁止进入替换。锁仍须保持；未登记、外部进程与持有者之间的竞争不能由该闸门保证。测试工程的 `DatabaseQuiescencePrototype` 只演示协议，未接入实际应用。
- **共享上下文边界（部分接入）：** `TargetContextCoordinator` 为主窗口的目标和旧模型业务登记外层操作与短生命周期上下文；排空时拒绝新操作，允许已登记操作的嵌套调用完成，等待操作及上下文释放，取消或释放失败后保持关闭，禁止操作等待自身排空。嵌套许可沿异步执行上下文传播，调用方必须等待其子任务完成，不能把它用于脱离操作生命周期的后台任务。旧式 Excel/GEDCOM 整表替换与协作树追加均在一个 SQLite 事务内提交，并在删除或写入后出错时回滚；实际恢复流程尚未使用该机制，不能据此宣称生产恢复安全。
- **应用级排空与正常退出：** 主窗口正常关闭事件先取消关闭并禁用主窗口，等待共享协调器排空，再请求关闭已拥有的子窗口；确认全部关闭后才允许主窗口关闭，应用的 `OnExit` 随后释放数据目录锁。等待超时、取消、子窗口拒绝或关闭异常时保持失败关闭并显示状态；菜单退出也走主窗口关闭路径。该机制不接入恢复，且不能保证进程强制终止、系统关机或直接调用 `Application.Shutdown` 等绕过普通关闭的路径。
- **隔离 WPF 验证：** 测试进程设置独立临时数据根目录，在 STA Dispatcher 上构造真实主窗口、预览、协作导入及备份对话框，调用窗口共用的初始化及业务方法；验证迁移、读取、导入、备份、排空后拒绝和数据库文件独占打开。目标关系/婚配专项在 SQL 写入或删除拦截点暂停后调用真实主窗口的普通关闭，断言排空期间拒绝新操作和第二租约，放行后确认原操作完整提交且窗口关闭。涉及 PowerShell 或 .NET 子进程、独占文件句柄和子进程中断的测试归入禁止并行的 `ProcessWorkerExclusive` xUnit 集合，避免 CI runner 上进程启动/回收彼此争用。测试不显示窗口，不证明人工视觉验收，也不覆盖超时、强制终止或生产恢复。
- **显示窗口与模态重入测试：** 单独运行的 `UI` 测试在隔离子进程显示透明主窗口和子窗口，并打开实际 Windows 保存文件对话框；测试在其模态消息循环中发起排空、取消对话框、释放活动连接，并验证成功或取消状态。该用例只验证保存对话框取消场景，不覆盖选择文件后提交、所有对话框、应用退出或人工视觉验收。
- **导入与关闭竞争验证：** 另一隔离 UI 测试显示主窗口和协作导入/备份对话框，以预先指定的虚构文件调用导入提交方法；SQLite 拦截器暂停实际成员插入，测试在暂停期间发起排空、拒绝新的备份提交并关闭主窗口，再释放插入并验证排空等待、数据结果及文件句柄释放。目录锁由测试显式持有，此结果不证明实际 `App.OnExit` 的锁生命周期；测试未通过 Windows 打开文件对话框选择该文件，也未触发导入确认消息框。
- **子窗口关闭边界：** 正常退出按上述顺序关闭 `OwnedWindows`；隔离进程验证了成功关闭、拒绝、异常、取消及在途操作超时。原生备份保存对话框在有或无其他登记连接时与正常退出竞争；另经真实主窗口备份事件进入 WPF `ShowDialog`，在原生选择框出现后请求正常退出，分别取消或确认默认文件名并校验生成的包，检查锁及子窗口生命周期。测试通过事件调用触发，非人工点击或视觉验收；不代表其他对话框均已覆盖。同步 `Closing` 处理程序阻塞 UI 线程时计时器无法抢占。生产恢复保持关闭。
- **退出入口与后台工作：** 当前源码唯一显式 `Application.Shutdown` 调用位于启动失败路径，释放已取得的目录锁后退出；系统会话结束、强制终止及未来直接调用 `Shutdown` 不受普通主窗口关闭协调保证。Excel、GEDCOM、协作 JSON 导出及备份创建、校验、预检从打开文件对话框开始到操作完成登记外层许可。隔离进程验证 GEDCOM 和协作导出的真实原生保存框取消、确认保存后的写入及正常退出；协作窗口实际以 `ShowDialog` 打开，成功/模拟失败提示出现时仍保持锁并等待提示关闭，GEDCOM 成功以状态文字提示、失败显示消息框。测试使用注入的临时目标路径及写入前暂停/失败回调，成功时执行真实文件写入；不代表人工视觉验收或覆盖写入中途的文件系统故障。
- **预览输出与退出：** PDF、XPS 和打印命令已登记输出操作许可。隔离进程验证 PDF、XPS 保存对话框取消、确认真实写入及确认后在发布前注入失败时的正常退出竞争；失败场景确认不生成目标文件、不遗留同目录临时文件并更新失败状态。XPS 成功场景检查实际生成 ZIP 格式的 `.xps` 文件。打印专项通过标题及标准 Windows 对话框类识别真实打印框，在框打开时请求正常退出并仅发送关闭消息取消；测试验证排空、锁保持与新操作拒绝，未点击确认或提交打印任务。同步打印或输出阻塞 UI 时，关闭协调的超时仍无法抢占。
- **XPS 文件输出：** `Services/PrintService.cs` 的 `ExportToXps` 直接使用 `XpsDocument` 将页面写入用户选择目录内的临时文件，成功关闭后才替换目标路径；它不查询或调用打印队列。无效路径、写入异常或发布前失败返回失败并清理临时文件。测试专用发布前回调只用于在已完整写出临时 XPS 后模拟真实文件系统发布失败，不参与生产行为。
- **版本化内部交换：** `GenealogyExchangeService` 定义 v1 JSON 文档，包含一个目标模型族谱及人物、关系、婚配、房支的原始字段和稳定 ID；预检会限制文件大小、拒绝不支持版本、无效/重复 ID、跨文档引用、无效房支树、无效人物关系与婚配（包括两方互换后的重复婚配）。默认 `ImportAsync` 在写入前报告来源族谱 ID 或各类记录 ID 冲突，且仅可将来源 ID 不存在的完整图数据作为新族谱写入；它不覆盖、删除或自动合并既有数据。显式 `ImportCopyAsync` 是唯一允许来源族谱 ID 已存在的入口：先执行同等文件、格式、结构及引用预检，再为目标族谱、人物、房支、关系和婚配全量生成新 ID，并重写 `GenealogyId`、人物 `BranchId`、房支 `ParentBranchId`、关系双方和婚配双方 ID；不得复用来源 ID，也不得按名称、世代或排行匹配。两条路径都在同一事务写入族谱、图数据和按 `GenealogyId` 隔离的来源记录；记录保存来源种类、导入模式、格式版本、来源族谱 ID、规范化文档 SHA-256 指纹及导入时间，不保存本机文件路径。任一拒绝、取消或写入失败均不留下部分数据。副本不复制附件，不自动合并，不取代恢复流程。
- **内部 JSON WPF 操作入口：** 文件菜单新增独立于旧“协作导入”的“导入内部 JSON…”入口，打开以主窗口为 Owner 的模态对话框。文件选择、预检和提交分别持有 `TargetContextCoordinator` 外层操作许可，正常退出会等待进行中的操作或用户取消文件框。用户选择绝对路径 JSON 后，使用短生命周期目标上下文调用默认或副本预检，显示格式版本、族谱名称、各集合数量、照片路径引用及分型拒绝原因；预检未通过时确认按钮不可用且不写入。默认模式预选，调用 `ImportAsync`；副本模式必须由用户显式切换、重新预检、输入 1–200 字符的显示名称并二次确认，调用 `ImportCopyAsync`。该名称只用于新族谱显示，绝不用于身份匹配、合并或覆盖。导入结果返回目标族谱 ID，成功后刷新族谱选择与关系清单并选中该目标；取消、拒绝或失败保持原选择和内存状态不变。隔离 UI 已覆盖原生文件框取消与正常退出竞争；默认冲突拒绝、副本 ID 重映射和写入失败回滚由隔离 SQLite 测试覆盖。不启动恢复流程。
- **外部格式预检与其他模态入口：** 照片选择、Excel/GEDCOM 导入文件选择、协作导入文件选择及其“确认导入”框均在显示期间持有协调器许可；正常退出会拒绝新操作并等待用户取消或结束相应模态框，再关闭拥有窗口。隔离 UI 测试分别在五个真实原生模态框出现时请求退出，验证锁仍持有、后续操作被拒绝，并取消文件选择或在协作确认框选择“否”。这些测试不接受外部文件，不覆盖照片实际读取或旧入口的完整解析。`ExternalGenealogyExchangePreflightService` 新增只读兼容 profile：`ExcelLegacyV1` 要求九列固定表头，以数据行序号解释父亲引用；可映射人物及生物父母关系，配偶姓名文本作为不可安全匹配的损失报告。`GEDCOM-5.5.x` 映射人物、`FAM` 父母/子女关系和双亲婚配，未支持标签进入损失报告，坏引用/版本/结构或反向重复婚配直接拒绝。两者只生成内存目标图，不写数据库、不替换旧成员、不按姓名匹配，也不属于恢复流程。旧模型导入在提交前检查空数据、重复/无效 ID、缺失父引用和导入内父子循环，整表替换及协作追加的数据库写入均由事务保护。
- **外部格式事务化导入：** `ExternalGenealogyExchangeImportService` 仅消费上述预检结果；错误或空目标图立即返回而不写入。有损结果必须以独立 `acceptLosses` 参数明确接受，未接受时保持零写入。预检成功后先记录原始文件 SHA-256，并在克隆目标图后、紧邻事务写入再次复核；两次读取不一致或任一次无法读取均追加 `SourceChangedAfterPreflight` 错误并拒绝，不创建任何记录。每次成功导入均生成新的族谱、人物、房支、关系和婚配 ID，调用 `GenealogyDataService.AddGenealogyAndGraphRecordsAsync` 在单一事务内保存完整图和 `GenealogyImportRecord`；来源记录保存 profile、格式版本与原始文件 SHA-256 指纹，不保存路径。该服务不选择既有族谱、不覆盖或自动合并，也不参与恢复流程。`ExternalGenealogyExchangeImportDialog` 以独立菜单入口显示 profile、映射数量、错误和分类损失，只能输入新族谱名称；有损时必须勾选独立确认，成功后主窗口刷新并选中结果。选择文件和提交均持有协调器许可；隔离 WPF 子进程已验证真实文件选择框和确认后事务写入在途的正常退出竞争、锁保持、新操作拒绝以及完整图和来源记录原子提交。
- **外部格式失败回滚：** 隔离 SQLite 测试在 GEDCOM 婚配记录写入时注入底层 I/O 失败（由 EF 包装为 `DbUpdateException`）；事务退出后族谱、人物、关系、婚配和来源记录均为零，不保留部分数据或来源追溯残片。
- 自动化测试优先覆盖迁移、关系校验、导入事务、备份恢复与布局数据投影。

- 在 Windows 原生环境使用 .NET 10 SDK 执行 `dotnet restore PuJiang.slnx`、`dotnet build PuJiang.slnx --no-restore --configuration Release`，以及日常测试 `dotnet test PuJiang.Tests/PuJiang.Tests.csproj --configuration Release --filter "Category!=Performance"`。

- 自动化测试以测试专用临时 SQLite 路径运行；不得启动会写入真实用户文档目录数据库的应用验证。
