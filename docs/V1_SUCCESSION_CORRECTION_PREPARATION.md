# V1 单一承嗣误录处理准备

状态：用户明确沿用拆支及重新挂接或删除，不单设复杂误录流程；拆支保留原生父母、出生处引用和嗣父母资料。四份契约已对限定场景定向协调，用户已批准单一嗣子拆支及重新挂接隔离实施，并对本次样本体验反馈“应该符合预期了”。保留现有工作台，仅使用独立虚构数据；按 D-033 不访问真实数据库、不做旧数据兼容或迁移。实际验证及人工验收状态见[接力](HANDOFF.md)。

## 场景和已确认方向

示例：丙原有生父甲及生母；先被登记为乙的嗣子，后来发现应由丁承嗣。用户进一步澄清：沿用拆支逻辑，丙带子女及后代拆成独立分支，保留生父母资料、甲处出生引用和原嗣父母资料；之后根据需要重新挂接或删除，重新挂接时按所选关系更新。此前“先解除原承嗣”应理解为拆出位置，不自动删除嗣父母资料。用户明确选择拆支，并非系统自行将后代迁回出生位置；独立分支承接及重新挂接的限定业务规则已定向协调。首批建议仅讨论 D-040 已建立的同谱单一承嗣；复杂多位置、多段嗣继和祧继不纳入本准备假定。

## 已有契约与实现

| 依据 | 已确认内容及适用边界 |
| --- | --- |
| 人物与亲属领域 §6、§7.1、§7.3、§8.4；[D-040](DECISIONS.md#d-040--v1-单一承嗣首批操作方向) | 人物身份、出生位置、嗣子位置和嗣继事实分别表达；出生处及生父母保留，嗣位承接后代，同一人物同时最多一个有效承接位置。 |
| 领域 §7.5、§9.1、未决 Q-01 | 解除当前承接位置时，不得自动把后代转到其他生子、嗣子或祧子位置；本次明确选择嗣子拆支时，独立分支承接后代，原出生处保留引用且不自动承接后代。Q-01 中其他承接位置解除情形仍待确认。 |
| 领域 §13；编修删除条款；[D-038](DECISIONS.md#d-038--v1-人物删除准备中的用户方向) | 删除关系或位置不必然删除人物及其他合法关系／位置；范围不能隐式扩大。D-038 普通整支删除、拆支的已确认规则不自动决定承嗣误录如何解除。 |
| 领域 §7.3、D-040；画布及编修承嗣补充 | 生母与嗣母各自独立；既有承嗣建立时按嗣父首位有效配偶默认嗣母、支持修改清空及限定补录。用户确认拆支时保留嗣父母资料；重新办理时的细节仍须核对，不将普通生母清空规则直接套用。 |
| 领域 §10.2；D-026/D-036 | 嗣继及跨代显示不能自行推断或改写已记录世代；D-039 普通挂接的世代差值规则不自动用于承嗣。 |
| 系统架构；画布及编修契约 | 通过统一业务命令和事务保护已确认的事实与位置；必要的影响展示、取消及焦点须按操作确定，不擅自改写原事实。 |

当前 [Application](../PuJiang.V1.Application/SuccessionApplication.cs) 仅提供承嗣创建、读取及嗣母修改；[隔离存储](../PuJiang.V1.Persistence/IsolatedSuccessionStore.cs)创建时将直接子位置转由嗣位承接；[分支存储](../PuJiang.V1.Persistence/IsolatedBranchStore.cs)拒绝对承嗣位置执行普通拆支。现有代码不提供承嗣解除或嗣父更正命令，不能用普通挂接代替。

进一步核对：现有承嗣创建要求来源是有父位置的普通出生位置，且该人物只有一个位置；解除后用户要求同时保留出生引用和独立分支，因此**现有创建入口不能直接重新办理**。当前子女投影通过现存承嗣事实识别出生引用；如果仅解除或移除该事实，不能据此假定出生引用仍能正确显示。后续须先明确可区分引用与唯一承接位置的事实表达，再按确认规则设计重新办理；上述是现状差异，不是实施方案。

## 契约定向协调结果

| 范围 | 当前约束与需要协调的表述 |
| --- | --- |
| 领域 §9.1、§7.1、§7.5 和 Q-01 | 补充用户主动选择的限定场景：独立分支是有效承接，生父处保留非自动承接的出生引用；保留 §7.5 及 Q-01 其他未决情形。 |
| 编修 §4.3 及拆支相关条款 | 补充嗣子按相同拆支逻辑处理、保留嗣父母资料，重新挂接按所选关系更新；不影响普通生子挂接。 |
| 画布 §10 拆支及删除边界 | 补充出生引用、独立承接分支及资料保留；沿用现有 PersonId + PlacementId 焦点、影响确认和取消保护。 |
| 系统架构删除与拆支补充 | 补充同一限定业务边界；保持统一命令、事务及隔离，不预设数据库实现。 |

用户已明确拆支保留嗣父母资料，重新挂接时按所选关系更新；这不等于已确认历史嗣继展示或已实施历史模型。契约已定向协调，不构成实施批准。

## 首批范围建议和依赖

建议只准备同一 Lineage 内 D-040 的单一嗣子位置拆支及其后再次挂接为嗣子；无后代和已有普通后代均覆盖。沿用工作台原有拆支入口及选择嗣父交互，按既有影响确认、事务及草稿保护核对。删除是用户允许采取的另一种处理方式；涉及承嗣位置的删除范围和保护尚未单独收敛，不默认纳入首批实现。祧继、多段历史嗣继、复杂多位置及跨谱操作均不扩展。

任务依赖：契约已定向协调，用户已批准隔离实施；设计和验证统一命令及投影，再衔接原有承嗣创建交互，使拆出人物可选择新的嗣父。每步均需验证确认、失败与重读，且不将数据库结构方案当作已确认业务规则。

## 待确认事项

1. **独立分支及出生引用：** 已明确独立分支承接后代，甲处继续保留出生引用且不自动承接后代；具体数据结构及投影在实施设计中确定。
2. **没有后代的解除：** 核对同一独立分支规则的适用及嗣位和嗣继事实如何处置；不能假定人物档案被删除。
3. **嗣父母和历史：** 用户确认拆支时保留嗣父母资料、重新挂接按所选关系更新；历史展示等细节仍须核对，不应自动发明历史业务规则。
4. **重新办理：** 用户确认更换嗣父时，即使此前主动清空嗣母，仍按新嗣父首位有效配偶重新确定；新嗣父无配偶则暂空，之后可按规则补录；重新挂接后再次主动清空继续受保护。该限定规则已协调四份契约；目标排行沿 D-040。
5. **交互与保护：** 入口在哪个位置、影响预览具体列什么、确认与取消、未提交草稿、排序变化及目标失效怎样处理；以简洁操作为原则，涉及不可逆影响的内容先明确。
6. **异常与范围：** 有效位置、关系、引用、后代和排序不一致、循环或其他复杂关系时怎样提示；不得静默猜测或扩大操作。已确认的无引用清理仅针对操作影响范围，不能删除仍被引用的人物。
