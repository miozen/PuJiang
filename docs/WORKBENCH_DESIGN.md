# 专业族谱编修工作台设计契约

本文件集中记录 [D-026](DECISIONS.md#d-026--专业族谱编修工作台与显式草稿) 用户确认的目标交互与建议实现边界；**不是现状或已交付承诺**。决策状态以 [DECISIONS](DECISIONS.md) 为准，横向图几何与未决规则见 [D-025](DECISIONS.md#d-025--横向世系图的参考布局定义) 和[横向设计](HORIZONTAL_LINEAGE_DESIGN.md)，阶段以[计划](CURRENT_PLAN.md)为准。

## 产品与工作区

- Windows 原生离线、单机优先的专业可视化族谱编修工作台；SQLite 是唯一权威数据源，多套族谱按稳定 ID 隔离。参考专业桌面工作台的组织方式，不复制第三方 UI。
- 三栏：左侧谱系管理，负责多套谱系的新增、选择、重命名及切换，不展示完整父子层级、不作为人物树导航；中间世系画布为主要录入和编辑入口；右侧为所选人物资料、婚配、亲属关系和操作。画布搜索直接定位人物。顶部菜单/工具栏和底部状态栏可辅助操作。侧栏可折叠、调宽并记忆布局；首期不做复杂自由停靠。持久化位置、版本、损坏回退属实现方案，尚未决定；不得用坐标推导业务关系。
- 画布顶部横列第一世、第二世等，一世一列；始祖位于左上，人物按本人谱载世代进入对应列。可直接在指定世代新增人物，无须先创建人物树或建立父子关系。父亲对齐排序第一子女，其他子女向下，各房支按完整可见子树占位；跨代与过继的连接及出继引用以 [D-026](DECISIONS.md#d-026--专业族谱编修工作台与显式草稿) 和[横向设计](HORIZONTAL_LINEAGE_DESIGN.md)为准。始祖的识别、无共同世代依据的人物定位等未决，不以缺少父母记录自动认定始祖。
- 工作台同一中央区域切换横向世系图与未来传统吊线图，业务编辑能力最终一致。共享稳定人物 ID、业务命令、编辑草稿和数据变更通知；各视图分别持有缩放、视口、展开状态和布局配置。切换视图不得丢弃草稿。现有 D-023 只读节点图保留作为辅助能力；D-008 的传统谱式和页面仍待样张确认，不能从此文推断版式已确定。

## 实施顺序与原型边界

先交付可运行的三栏 WPF 原型，使用内存虚构样本验收一世一列、始祖左上、首子对齐、可见子树占位、未关联人物、跨代正交连线、过继引用、选中、展开折叠、缩放和平移。原型中新增或编辑若提供，仅操作内存样本，界面应清楚说明不持久保存，不读取或写入真实族谱数据库。原型验收后再逐步复用现有业务及布局能力；统一保存与数据库集成及阶段回归在其后，真实持久写入须遵守本文件的草稿、统一命令和事务规则。现有过渡界面和已有能力保留。具体阶段与验收见[计划](CURRENT_PLAN.md#p2--交互式世系图)。

## 已确认的画布输入规则

| 输入 | 目标行为 |
|---|---|
| 左键单击人物 | 选中唯一焦点，自动展开其直接子女并显示其配偶；保留其他已展开房支。 |
| 切换焦点 | 隐藏上一焦点的配偶并显示新焦点配偶，不自动折叠其他已展开房支；遇有旧人物未保存草稿先按下节处理。 |
| 左键空白 | 取消选中并隐藏配偶；按住空白拖动平移画布。点击与拖动的阈值和取消边界需实测。 |
| 右键人物 | 选中该人物并显示人物快捷菜单，不触发左键自动展开子女；旧人物草稿处理完成前不得提交焦点变更。 |
| 右键空白 | 显示画布快捷菜单。 |
| 鼠标滚轮 | 以鼠标位置为中心缩放，缩放上下限与触控板适配另作实现验证。 |
| 普通拖动人物 | 不直接修改谱系关系；是否允许临时调整布局及其存储方式未决定。 |
| Esc | 根据交互状态退出当前操作、关闭菜单或清除焦点；冲突优先顺序与草稿检查须在实现前形成可测试方案。 |

同一时刻仅一个焦点；焦点、已展开人物集合、各视图状态和编辑草稿是四类独立状态。配偶仅随当前焦点显示；身份与婚配语义不由位置或姓名推断。延迟加载配偶/子女的结果须受谱、人物、视图、请求版本和取消状态约束，不得在焦点变化后回填旧结果。

## 业务编辑、草稿和命令

- 两个视图最终均可编辑人物、新增子女/配偶/兄弟姐妹、调整同胞顺序、修改人物关系、管理房支与继嗣、安全删除；人物、子女、配偶新增及关系建立、解除由画布和右侧面板完成。视图交互不同，业务命令、校验和持久化共享。首期不要求多人物批量编辑。
- 草稿按谱和人物身份关联，属性变更先写入草稿而非 SQLite；默认每次编辑或新增一个人物显式保存。保存前校验并确定完整写入范围，在事务内执行关系、循环、同谱、删除影响、并发与版本检查；失败保留草稿和明确原因。新增人物及相关关系如属于同一次保存，必须整体提交或回滚。
- 不同人物之间切换提示**保存 / 放弃 / 取消**；取消保留原人物、草稿和状态。切谱、窗口关闭、退出先检查草稿；同一人物切视图保留。成功提交后发出数据变更、更新相关视图并尽量保留视觉锚点；若提交成功但后续刷新失败，报告“已保存但刷新失败”，不得重试成重复写入或谎报未保存。只读视图和现有直接写入入口的渐进迁移需明确，不能假称全局草稿已经存在。
- 菜单、右键、工具栏、快捷键及属性面板通过统一的应用命令入口、参数、可用性和失败反馈调用既有领域服务；目标命令边界须覆盖校验、权限/数据范围、事务与提交后的通知。布局计算与绘制不直接写数据库。
- 建议默认：`Ctrl+S` 保存、`Ctrl+F` 搜索、`F2` 编辑、`Esc` 取消、`Ctrl+0` 最大化画布、`Alt+Left/Right` 导航；`Ctrl+Shift+P` 命令搜索为后续。支持可配置快捷键并检测冲突；“最大化画布”与适配画布/缩放归一的具体行为及快捷键冲突处理为 Proposed，不能静默更改用户指定含义。
- 预留历史/撤销的命令边界，但在可靠历史、事务和恢复机制未实现前不暴露虚假的撤销重做。长期历史考虑操作类型、时间、对象、修改前后、来源/修订说明；谱载原文、人工整理、系统推导须可区分，不因此承诺现有数据库已具备审计日志。

## 数据一致性与性能边界

保持 D-002/D-003/D-004 的同谱隔离、关系原始信息和谱载权威；D-022 的主线选择/失效复核、D-025 的固定世代列继续适用。事务与既有唯一约束、循环检查、删除保护共用；对多配偶、过继、继嗣及未详关系不以姓名或画布位置自动推断。数据版本和异步加载必须防止旧谱、旧选择或旧视图结果回填；批量风险及失败状态要可见。

横向画布应有按需数据读取、独立于 WPF 的布局结果、视口裁剪、视图锚点、搜索定位和导航历史；为展开/折叠及保存刷新分别测量视口偏移，避免无必要跳动。D-024 既有节点图的性能验收不自动成为横向视图的性能阈值。生产恢复在真实数据正式使用前仍需按 D-014 完成专项验收；数据库快照不是附件/配置完整备份，不因本目标放宽。先使用简单、可测试的模块边界，不预先引入复杂基础设施。

## Proposed：实施前最小待确认项

2. D-025 的多根/缺失与冲突世代、文本排行/指定顺序及其持久化、多婚配/跨支和不可避免交叉；详见[横向设计](HORIZONTAL_LINEAGE_DESIGN.md)。先使用显式、无冲突的输入建设纯布局切片，不能把示例约束推广为业务决定。
