# P2 横向世系图：审查与设计草案

## P2-1 纯布局切片的实现边界

`HorizontalLineageLayout` 接收显式人物 ID、非负世代列和同胞顺序、有限正尺寸、父子边及展开 ID；先校验全部输入，再计算可见森林。当前仅支持每人至多一条父边且父子处于相邻列；缺失引用、重复 ID 或同胞顺序、多父边、跨代及无效尺寸均明确拒绝。这是算法切片的输入限制，不是对真实族谱业务规则的决定。布局以完整输入尺寸计算固定列距、按子树分配纵向位置并生成正交边，输出只读结果；不依赖 WPF、SQLite，也不修改输入。复杂交叉、按需数据库和画布仍未实现。

输出的节点边界和中心、连线转折必须可由浮点数表示，否则失败而不返回部分结果；这不保证任意规模的数据均可布局。多根及混合尺寸固定样本验证不相关边交叉、节点避让、列一致和输入顺序确定性；测试与 CI 的实际状态见[接力](HANDOFF.md)。

本文件是 D-025 的实现设计草案，不替代 [决策](DECISIONS.md#d-025--横向世系图的参考布局定义)。本轮仅依据用户列出的十项文字要求；未取得或审阅参考截图，像素、样式和细节须待样张核对。现有 [D-023](DECISIONS.md#d-023--目标模型只读节点连线图) 节点图保留；这不是 P3 传统吊线图。

横向图在目标工作台中的焦点、配偶、展开集合、草稿、鼠标和命令规则以 [D-026](DECISIONS.md#d-026--专业族谱编修工作台与显式草稿) 及[工作台设计](WORKBENCH_DESIGN.md)为准。用户要求新工作台画布单击人物自动展开直接子女；D-021 已验收的现有只读树形路径高亮及折叠语义保留，不将新行为静默套用到旧视图。横向图和未来传统视图的布局、视口和展开状态独立，但共享人物 ID、业务命令、草稿和数据变更通知；这些均是目标，尚未接入。

## 已确认的纵向布局规则

每一代固定一列，父节点与排序第一的子女在同一水平线上；其余子女依次向下排列。每个房支都递归使用此规则，使各自的首位子女水平向右延伸，不以全部子女的中心对齐父节点。布局必须按整个**可见子树**占位：例如长子后代展开后，次子及其可见后代整体位于长子整棵可见子树下方。展开、折叠后重新计算占位，保持节点不重叠、不相关连线不交叉，并保留正确的正交父子连线。此规则适用于任意层级和各房支；同胞顺序只使用已确认的输入，不推断谱载排行。

2026-11-04 审查发现的首位子女对齐缺陷已修正；历史反例与测试方案见本文件末尾，当前验证见接力状态。

## 分层方案（建议，尚未实施）

1. **查询与一致性。** 以 `GenealogyId` 和有效数据版本为边界提供有界的根/子代、人物详情、婚配及按 ID 搜索/路径查询，使用稳定游标和取消机制；响应携带版本，批次来自不同版本时禁止拼接，提示刷新。明确搜索定位未加载人物时的路径查询和补载；切谱、刷新及过期操作失败关闭。按需加载需要证明每次数据库查询范围有界，不能仅将完整快照缓存后称为按需加载。必要的轻量索引、总数、一次性版本读取及其内存/访问量应单独说明并测量，不假定当前全库代数可凭空提供跨多个连接的历史快照。
2. **投影与世代列。** 输入为已确认的单谱主线、明确世代与排序结果，输出稳定人物 ID、世代列索引、同胞顺序、房支和配偶附属信息；数据与来源分离。跨分支同代使用同一全局列映射，不以展开时的局部深度单独决定列。缺失、冲突、不可比较或不连通时返回可见问题，不伪造对齐、排行或关系。谱载值不被自动覆盖；指定顺序的数据归属和持久化须先决定。
3. **纯布局引擎。** 不依赖 WPF、EF、`LineageTreeNode` 或数据库；输入为已验证的投影、展开集合、节点尺寸、确定的世代列和顺序；输出不可变的节点矩形、世代列、房支区域、配偶附属矩形、带关系 ID 的正交折线路径、图形边界和无法布局的诊断。祖先到后代严格向右；每列的 X 按列索引确定；同胞沿 Y 按确认顺序排列。纵向按上节首位子女水平对齐与整棵可见子树占位规则计算；在列间通道计算水平/垂直折线，展开或折叠后重算。兄弟边共用连接干线的接触和汇合须与不相关边的交叉区分；对无法同时满足列、顺序和零交叉的输入显式失败或提示待处理，不得静默改列、改变谱载或假称满足。路由算法与复杂跨支关系的可行性在实现前用反例验证。
4. **WPF 呈现。** 渲染层消费布局结果，不重算父子语义或世代；`ScrollViewer`、缩放变换、ID 命中测试、选中/路径高亮以及视口加缓冲区按需创建可视元素。正交折线采用可裁剪的路径或批量绘制；缓存按投影版本与展开状态失效。滑动和缩放不重新读取全谱；展开时按需读取下一层、重排并保持用户可理解的视口位置。异步结果必须绑定族谱/版本/请求状态，过期不回填。
5. **接口方向。** 建议分为 `ILineageProjectionReader`（分页和版本）、`HorizontalLineageProjection`（世代/同胞顺序与诊断）、`IHorizontalLineageLayout`（不可变输入输出）、独立 WPF 适配器/视图状态。接口名称和存储结构均为草案，不要求以现有显示类作为领域模型；不引入持久化迁移直到指定顺序等业务语义确定。

## 实施前须确认的冲突边界

- 多个不连通根、缺失谱载世代、同一人物谱载世代与选定父母链不一致时，如何确定绝对列或标明不能对齐？“同代”以何种已确认资料或映射为依据？不能仅因深度相同就推断全谱同代。
- `RecordedBirthOrder` 是文本而非已排序数字；中文排行、重复、缺失或不一致时，是否以及如何允许显式指定展示顺序，是否按图表保存？不能把字符串排序说成谱载排行规则。
- 多婚配、同一配偶也在主线作为独立人物、未知配偶以及跨支关系如何显示或引用，如何避免重复人物和语义丢失？
- 当既定世代列、指定同胞顺序、房支边界及复杂关系使零交叉不可行时，哪些关系纳入本图，如何呈现冲突及人工处理？不得以技术折中改变已确认规则。
- 大数据情况下采用何种一致性与版本机制、查询计数及性能阈值；现有 D-024 是已有节点图的验收，不能自动当作横向图承诺。

## 真实谱系只读投影：实施前评估（2026-11-04，建议，待用户确认）

### 已有基础与缺口

- `Person` 的谱载世代和排行都是可空自由文本，推导值为独立可空整数；目前没有通用、已确认的文本解析及人工确认状态。人物、关系、婚配和房支有稳定 ID，婚配不表示子女属于哪一段婚配。
- 现有 `GenealogyGraphSnapshot` 在单个读事务中读取整谱及全库代数；`LineageProjectionSession` 保留所有人物、父母候选和失考记录，唯一父母候选自动选择，多候选显式选择，不按首选标记自动选线。图表配置已保存父母选线和失效身份快照，但不保存世代映射或同胞顺序。
- 横向布局只接收显式列、显式顺序及每人至多一条父边、父子相邻列的森林；不支持直接处理多父母、跨代及复杂婚配。固定样例用户确认不证明真实数据能直接接入。
- 现有完整快照可用于小规模隔离设计验证，不满足 D-025 的真实数据按需加载；不能以“仅裁剪可视控件”或读取整谱缓存冒充按需查询。

### 待用户选择的规则（以下均为 Proposed）

1. **世代列与缺失、冲突。** 建议只把用户确认的谱载世代映射用作全谱列依据；连接的父子若世代缺失，可在用户显式选择后按所选父子链建立带“推导”标记的临时列，不改谱载；相互矛盾或跨代的关系显示原值、原因和处理入口，隔离到问题列表，不能假装相邻或隐藏记录。没有共同世代依据的不连通分支分别显示并明确标注“相对列，未确认跨支同代”；是否允许同一画布分别呈现、以及哪些谱载文本可归一为同一世代，须确认。备选为缺失或无共同依据时均不绘图，等待人工补齐；较严格但影响浏览。
2. **同胞顺序。** 建议把谱载排行原文完整展示；仅在一组同胞的可比较排行均有唯一、无歧义结果且规则经确认时使用解析顺序。缺失、重复、不可比较时，请用户在该组显式排列，草稿只影响展示；未经选择的组在问题列表中保留全部人物，不按姓名、ID 或数据库顺序暗示排行。建议优先会话内保存，确认是否需要按图表持久保存及何时失效；备选是允许标明“临时未确认顺序”的稳定展示，便于立即浏览，但首位子女只是临时位置。解析“长、次、三”等文本的具体范围和女性/继嗣的排序含义不可自行决定。
3. **复杂关系和配偶。** 建议沿用 D-022 的唯一父母候选自动展示、多候选显式选择、失效须复核；其他候选和失考在人物详情/问题清单可见，保持原关系。每条婚配在人物卡片附属区列出对方和关系身份，未知对方写“未详”；配偶亦为谱系人物时，附属引用指向同一人物，允许定位其主节点，不创建第二个人物。多婚配分别列出，不根据婚配推断子女归属或婚配顺序。跨代、跨支或无法按当前布局表达的选中关系保留诊断与定位，不伪造连线；是否接受附属引用与不绘制复杂关系线的首期体验须确认。现有有方向配偶关系与无向婚配分别呈现、保留来源，不自动合并。

### 可操作实施建议（待规则确认）

1. **规则和最小切片。** 用户确认上述取舍及文本处理范围后，在决策文件记录接受的边界；优先做只读单谱、明确主线、列和顺序的横向投影，复用现有固定样例布局及图表选线，逐项暴露未决数据。不修改人物谱载和原始关系；暂不接入编辑、生产恢复或自动合并。图表保存扩展若被批准，再单独设计迁移、失效及备份兼容，不假定现有图表支持这些字段。
2. **按需读取与一致性。** 设计按族谱、选线和数据版本约束的根节点/直接子代、人物与婚配、搜索和祖先路径查询，指定分页、上限、取消、稳定顺序；每批绑定请求及版本，变更时丢弃结果并要求刷新。须验证版本覆盖人物、关系、婚配、房支与图表配置等投影依赖；全库代数及图表版本的覆盖和数据库替换边界须逐项核实，不能把单个计数器当作跨连接历史快照。查询可能需要轻量索引或预计算，其全谱成本须公开测量。实现前用隔离数据库证明查询边界与一致性。
3. **呈现与诊断。** 仅已确定列、顺序和可表达父边送纯布局；未决项在可见问题列表保留稳定 ID、原值、原因、对应人物及处理入口，并明确可能缺少的关系。不得因一个异常静默丢弃整谱或自动更改数据。连线绑定关系 ID；展开折叠重新计算整个可见子树。复杂数据是否允许部分图与问题并列，取决于以上规则确认。
4. **验收。** 隔离两谱样本覆盖同名、单一/多父母、失考、多婚配、配偶也是主节点、缺失和冲突世代、不可比较/重复排行、跨代及断开根；验证原始数据不变、诊断可见、跨谱隔离、过期请求丢弃及失败关闭。WPF 与用户人工验收固定列、首子对齐、占位、正交线、搜索和问题导航。记录实际数据库查询数/返回行、创建控件数、布局时间、内存及设备；横向图性能阈值先测基线再确认，不能挪用 D-020/D-024。执行 Release 构建、日常测试和独立 UI/性能专项。

这些建议不改变 Accepted 决策，尚未获批准，也不代表已实现。D-014 的生产恢复、自动合并和按谱候选切换继续关闭，真实数据正式使用前仍须恢复专项验收。
