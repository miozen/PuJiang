# P2 横向世系图：审查与设计草案

## P2-1 纯布局切片的实现边界

`HorizontalLineageLayout` 接收显式人物 ID、非负世代列和同胞顺序、有限正尺寸、父子边及展开 ID；先校验全部输入，再计算可见森林。当前仅支持每人至多一条父边且父子处于相邻列；缺失引用、重复 ID 或同胞顺序、多父边、跨代及无效尺寸均明确拒绝。这是算法切片的输入限制，不是对真实族谱业务规则的决定。布局以完整输入尺寸计算固定列距、按子树分配纵向位置并生成正交边，输出只读结果；不依赖 WPF、SQLite，也不修改输入。复杂交叉、按需数据库和画布仍未实现。

输出的节点边界和中心、连线转折必须可由浮点数表示，否则失败而不返回部分结果；这不保证任意规模的数据均可布局。多根及混合尺寸固定样本验证不相关边交叉、节点避让、列一致和输入顺序确定性；测试与 CI 的实际状态见[接力](HANDOFF.md)。

本文件是 D-025 的实现设计草案，不替代 [决策](DECISIONS.md#d-025--横向世系图的参考布局定义)。本轮仅依据用户列出的十项文字要求；未取得或审阅参考截图，像素、样式和细节须待样张核对。现有 [D-023](DECISIONS.md#d-023--目标模型只读节点连线图) 节点图保留；这不是 P3 传统吊线图。

横向图在目标工作台中的焦点、配偶、展开集合、草稿、鼠标和命令规则以 [D-026](DECISIONS.md#d-026--专业族谱编修工作台与显式草稿) 及[工作台设计](WORKBENCH_DESIGN.md)为准。用户要求新工作台画布单击人物自动展开直接子女；D-021 已验收的现有只读树形路径高亮及折叠语义保留，不将新行为静默套用到旧视图。横向图和未来传统视图的布局、视口和展开状态独立，但共享人物 ID、业务命令、草稿和数据变更通知；这些均是目标，尚未接入。

## 分层方案（建议，尚未实施）

1. **查询与一致性。** 以 `GenealogyId` 和有效数据版本为边界提供有界的根/子代、人物详情、婚配及按 ID 搜索/路径查询，使用稳定游标和取消机制；响应携带版本，批次来自不同版本时禁止拼接，提示刷新。明确搜索定位未加载人物时的路径查询和补载；切谱、刷新及过期操作失败关闭。按需加载需要证明每次数据库查询范围有界，不能仅将完整快照缓存后称为按需加载。必要的轻量索引、总数、一次性版本读取及其内存/访问量应单独说明并测量，不假定当前全库代数可凭空提供跨多个连接的历史快照。
2. **投影与世代列。** 输入为已确认的单谱主线、明确世代与排序结果，输出稳定人物 ID、世代列索引、同胞顺序、房支和配偶附属信息；数据与来源分离。跨分支同代使用同一全局列映射，不以展开时的局部深度单独决定列。缺失、冲突、不可比较或不连通时返回可见问题，不伪造对齐、排行或关系。谱载值不被自动覆盖；指定顺序的数据归属和持久化须先决定。
3. **纯布局引擎。** 不依赖 WPF、EF、`LineageTreeNode` 或数据库；输入为已验证的投影、展开集合、节点尺寸、确定的世代列和顺序；输出不可变的节点矩形、世代列、房支区域、配偶附属矩形、带关系 ID 的正交折线路径、图形边界和无法布局的诊断。祖先到后代严格向右；每列的 X 按列索引确定；同胞沿 Y 按确认顺序排列。自底向上计算展开子树/房支占用的纵向区间，再按稳定顺序放置并在列间通道计算水平/垂直折线；展开或折叠后重排受影响区域，所有可见节点不重叠且父子边无非约定交叉。兄弟边共用连接干线的接触和汇合须与不相关边的交叉区分；对无法同时满足列、顺序和零交叉的输入显式失败或提示待处理，不得静默改列、改变谱载或假称满足。路由算法与复杂跨支关系的可行性在实现前用反例验证。
4. **WPF 呈现。** 渲染层消费布局结果，不重算父子语义或世代；`ScrollViewer`、缩放变换、ID 命中测试、选中/路径高亮以及视口加缓冲区按需创建可视元素。正交折线采用可裁剪的路径或批量绘制；缓存按投影版本与展开状态失效。滑动和缩放不重新读取全谱；展开时按需读取下一层、重排并保持用户可理解的视口位置。异步结果必须绑定族谱/版本/请求状态，过期不回填。
5. **接口方向。** 建议分为 `ILineageProjectionReader`（分页和版本）、`HorizontalLineageProjection`（世代/同胞顺序与诊断）、`IHorizontalLineageLayout`（不可变输入输出）、独立 WPF 适配器/视图状态。接口名称和存储结构均为草案，不要求以现有显示类作为领域模型；不引入持久化迁移直到指定顺序等业务语义确定。

## 实施前须确认的冲突边界

- 多个不连通根、缺失谱载世代、同一人物谱载世代与选定父母链不一致时，如何确定绝对列或标明不能对齐？“同代”以何种已确认资料或映射为依据？不能仅因深度相同就推断全谱同代。
- `RecordedBirthOrder` 是文本而非已排序数字；中文排行、重复、缺失或不一致时，是否以及如何允许显式指定展示顺序，是否按图表保存？不能把字符串排序说成谱载排行规则。
- 多婚配、同一配偶也在主线作为独立人物、未知配偶以及跨支关系如何显示或引用，如何避免重复人物和语义丢失？
- 当既定世代列、指定同胞顺序、房支边界及复杂关系使零交叉不可行时，哪些关系纳入本图，如何呈现冲突及人工处理？不得以技术折中改变已确认规则。
- 大数据情况下采用何种一致性与版本机制、查询计数及性能阈值；现有 D-024 是已有节点图的验收，不能自动当作横向图承诺。

## 可操作验收矩阵（建议）

| 范围 | 样本与动作 | 可检查结果 |
|---|---|---|
| 世代列 | 固定多根、多分支和至少四代样本；改变展开顺序、折叠再展开 | 相同已确认世代 X 相等，不同世代按固定列向右；分支变化不导致同代错列，重复运行输出一致。缺失/冲突不得静默对齐。 |
| 排序与重排 | 多兄弟、嵌套房支及长姓名；按确认的谱载/指定顺序逐支展开 | 同辈纵向顺序符合确认规则，节点矩形不相交；展开/折叠后仍满足列与顺序。排行不可比较、缺失和重复的处理按已确认规则检验。 |
| 连接 | 检查每段坐标与关系 ID；兄弟共干线、多支及视口边界 | 每段水平或垂直，父子端点绑定正确节点；不相关边/节点不相交，共干线汇合另行定义；不可行样本显式报告，不得静默错连。 |
| 配偶 | 已知、未知、多配偶及配偶本身也为谱系人物 | 根据确认的展示规则附属于人物，不占下一世代列；身份和原始婚配不丢失，重复/复杂情况的处理有明确提示。 |
| 交互 | 深链、宽分支、平衡谱；分次展开、折叠、双向滚动、缩放、同名/ID 搜索定位 | 查到正确 ID，未加载目标按需补载路径并高亮；缩放及边界滚动不漏画节点/穿越视口的线；切谱、取消或数据版本变化不显示旧结果。 |
| 按需与性能 | 固定千人及更大虚构谱，记录每次数据库查询、返回行、创建控件数、布局耗时、内存和环境 | 首次及每次展开不以完整人物/关系记录的全谱读取或全节点可视元素为前提；比较折叠、逐次展开及搜索前后计数。可量化阈值在基线测量后确认，不挪用 D-024。 |
| 数据与回归 | 独立 SQLite，两谱同名、多父母候选、失考、无效关系和过期操作；真实 WPF 及人工验收 | 单谱隔离，旧记录与代数不因只读浏览改变，未决关系不自动选线，过期/取消无陈旧回填；执行本地日常测试和独立 UI/性能专项。 |

本设计不启用 D-014 暂停的自动合并、生产恢复或按谱候选切换，不扩展极端并发专项。实施前先用固定样本和反例细化可行性、完成待确认规则及验收门槛，再进入开发。
