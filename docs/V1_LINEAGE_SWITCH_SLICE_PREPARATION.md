## 已确认的契约边界

| 主题 | 已确认要求及依据 |
|---|---|
| 项目与隔离 | 一个 Genealogy 是独立修谱项目，包含谱文与多个独立 Lineage；人物身份、亲属、婚配、世系位置、排行及配偶排序归各自 Lineage，不自动共享或同步。依据：系统总体架构 §1.2、人物与亲属关系领域模型 §2.1–2.2、D-029/D-031。 |
| 空谱系 | 当前项目下允许创建空谱系，不自动生成虚拟人物；也允许创建时同时录入首节点，但不是强制流程。单独新增真实首节点仍可后续执行。依据：谱系管理与编修 §2.1、画布工作台交互 §3.1–3.2。 |
| 创建信息 | 谱系基本信息包括名称、所属分类、主题名、地区、郡望堂号和备注；项目主姓氏属于 Genealogy，不在单个谱系创建窗口重复设置。字段必填、重名和分类选项等规则尚未据此推定。依据：谱系管理与编修 §2.1–2.2、画布工作台交互 §3.3。 |
| 创建结果 | 成功后进入新谱系画布；空谱显示空画布，未选中人物时右侧保持未选中。仅创建空谱不得造人；若提供同时创建首节点，谱系、人物、位置及必要关联须同一事务提交或回滚。依据：画布工作台交互 §3.2。 |
| 焦点 | 人物焦点由 PersonId + PlacementId 确定；切换谱系或焦点失效必须清除无效操作上下文，不得从姓名或 PersonId 猜测结构位置。依据：谱系管理与编修 §1.4、画布工作台交互 §2.3、架构 §5.2。 |
| 普通编辑与失败 | 普通编辑在已确认的完成事件进入统一 Command 自动保存，并非逐字写入；失败保留输入、展示错误、允许修正重试，阻止会丢失未提交输入的导航；提交中及结果不确定时避免重复提交。依据：架构 §8.1–8.6、交互 §8.1–8.3、D-029。具体切谱交互顺序不由此文擅自补定。 |
| 草稿上下文 | 子女草稿锁定 Lineage、父 PersonId、PlacementId 和必要顺序版本；谱系变更或位置失效不得静默提交至新上下文。相同 Lineage 的两种 ViewMode 共用事实、顺序、命令和编辑状态；显示状态可以独立。依据：D-031、交互 §2.2、架构 §11.3。 |
| 安全范围 | 保留现有 WPF 工作台及测试，先使用隔离虚构数据库；不访问、迁移或修改真实用户库，不做旧数据转换或跨谱共享。复制、合并、复杂过继及完整吊线图不属于本准备的默认首批范围。 |

## 最小实施任务及依赖（建议，未实施）

1. **隔离谱系创建与基本资料：** 在新隔离库设计创建 Command、基本信息及项目主姓氏校验，保留契约列出的资料；创建空谱及操作记录的事务/回执、失败和重复提交处理一起验证。分类来源、同名处理、主姓氏缺失的提示与非必填信息呈现属于实施设计细节，不从当前模型推定。
2. **首页只读投影：** 按 GenealogyId + LineageId 校验并读取已提交事实；计算当前谱真实人数、男女人数和占比，区分未知性别及零人数；返回所有有效首节点的 PersonId + PlacementId。若还展示位置/画布节点数，应另行标清口径，不与人物总数混用。上述具体首页组合为建议，7.2–7.3 的完整分类分析仍须单独实现与验收。
3. **可追溯操作日志：** 新建适用于本隔离切片的用户可读记录，建议先覆盖新建谱系和本切片新增首节点等实际接入的成功业务操作，明示记录起点及范围；具体事件清单、显示字段与保留周期需在实施范围确认时审定。操作和日志同事务、去重、隔谱、失败不记成功；不可把原有回执当作完整历史，不承诺撤销或补造既往记录。
4. **首页及首节点入口：** 保留三栏工作台，切谱显示当前谱首页、明确进入修谱按钮，并允许从具体首节点进入；空谱仍可进入画布。可取消的首节点资料提示应真实保存确认纳入的字段，取消不创建 Person/Placement。多个根的显示只读支持与新增多根能力分别评估，不假定必须依数据库自然顺序选一个。
5. **切换与编辑安全：** 复用现有 Command、草稿和失败保护，未保存信息切谱提示保存；校验 GenealogyId/LineageId 与 PersonId/PlacementId、异步请求上下文，避免将结果回填到另一谱。普通录入保持简洁，不进入复杂关系编修。
6. **验证与用户复验：** 在同一应用进程内用全新隔离虚构项目创建两谱，覆盖下表、现有 D-030/D-031 及窗口回归；不退出应用、不访问真实数据库。通过本切片不代表复杂关系、完整统计、历史记录或吊线图完成。

依赖顺序：任务 1 是任务 2–5 的基础；任务 2、3 的读取可与任务 4 集成，任务 4–5 完成后进行任务 6。操作日志的事件范围和首节点资料字段承载须在最终实施范围中明确，避免界面承诺超过真实数据。

## 用户已确认的交互方向

- 创建时必须保存谱系名称、所属分类、位置、主题名、姓氏，五项均为必填。用户明确“位置”即地区；姓氏使用项目主姓氏，不在谱系中建立独立可修改的主姓氏。不据此删改契约中已有的郡望堂号和备注等字段。
- 先创建空谱，不在创建谱系事务中同时录入首节点。打开画布时可弹窗提示录入首节点的姓氏、谱名、主世系、称谓和备注；用户可以取消不录入。取消后谱系仍为空，不创建虚拟人物。用户明确“主世系”是以房头为一世的世代：例如当前人物为第八世，则为八世；这不授权根据布局自动覆盖显式世代或推断未记录的房头。
- 切换谱系时，如有尚未保存的信息，提示保存；录入错误可后续修改。正常录入应保持简洁，遵守既有自动保存及失败保留输入规则，不将常规切换扩大为复杂审批流程。保存失败或结果不确定时不能静默丢稿或误报成功。
- 切换后显示该谱系的节点统计、首节点和操作日志等信息；提供“进入修谱”按钮，也可通过点击首节点进入画布。空谱尚无首节点时仍须提供进入修谱的路径。操作日志的可用范围和真实来源须核对，不将未实现的可靠历史或撤销宣称为已有。
- 本次不要求退出应用、跨进程重开；在同一应用进程的隔离样本中验证。

## 剩余待确认事项

下列问题在已确认契约的边界内，不能自行当作新规则落地：

1. **已协调的姓氏、地区和主世系：** 用户已明确沿用项目主姓氏、“位置”指地区、主世系是以房头为一世的世代，与现有契约不冲突。若项目主姓氏缺失，如何引导用户完善项目资料需在实施设计中处理，不能在单谱窗口静默建立第二份主姓氏。
2. **字段及呈现细节：** 必填五项之外，契约已有的郡望堂号和备注如何在首批呈现和保存；所属分类选项来源、同名谱系显示、字段长度等技术/产品细节待核对。不能把未回答解释为删除契约字段。
3. **首页统计与操作日志：** 明确节点统计口径、多个首节点如何展示；操作日志需明确来源与本切片可支持的范围，不能将技术回执当作完整用户操作日志，也不能虚构历史。可先核对现有可复用能力，再区分已存在与待设计项。
4. **切谱保存提示的异常边界：** 用户已确认未保存时提示保存。保存失败保留输入并允许修正；进行中或结果不确定须等待/安全重试，不得跨谱回填。提示具体按钮和当前输入取消行为遵守既有契约，普通录入不增加无必要的确认步骤。
5. **焦点及视口：** 切谱首页与画布之间的焦点、缩放和视口是否恢复，尚待核对；不同谱不能携带无效 PersonId + PlacementId。目标读取失败不能显示新旧混合事实。

## 建议的最小实施边界（待确认）

- 当前虚构项目内创建空 Lineage，列出并切换至少两条谱系；切换进入该谱系首页，展示节点统计、首节点和操作日志，提供进入修谱按钮及首节点入口；打开空画布可取消的首节点信息提示。创建字段遵守用户确认内容及上方待确认结果，不将“当前模型只支持 Name”作为删减契约字段的理由。
- 创建和普通编辑分别走统一 Application Command；谱系数据及必要回执在事务中提交，重复请求和未知结果安全处理。读取、投影、焦点和异步回填按当前谱上下文隔离；画布与旧工作台保留。
- 先不做项目创建/切换、谱文、谱系复制和合并、谱系删除、同时创建首节点、复杂多位置及传统吊线图；不对缺失规则或旧数据进行自动补全。这是分期建议，须在实施范围确认时审定。

| 重读 | 不退出应用；在同一隔离样本内重读，必要时关闭并重开工作台，各谱身份、顺序和关系稳定。 |
| 保留现状 | 已验收三栏、D-030/D-031 交互和旧工作台保留；隔离测试、相关 WPF、Release 构建、完整日常测试及用户实操分别报告。 |

## 明确不推断

谱文的实体/格式与传记关联、复制时配偶顺序、分类词表、命名唯一性、复杂关系和真实库迁移均不由本准备决定。不要以单一虚构测试的两谱通过宣称双 ViewMode、完整谱系管理或生产数据已验收。
