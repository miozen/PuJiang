# D-040 后 V1 隔离切片候选

本轮只整理候选、前置条件及验收目标，不决定业务规则、不批准实施。保留现有 WPF 工作台，仅使用独立虚构数据，不访问真实数据库；按 D-033 项目完成前不做旧数据兼容、迁移或转换。历史行第按 D-037 暂缓，不作为下一项候选。

## 当前基线

- [D-040](DECISIONS.md#d-040--v1-单一承嗣首批操作方向) 已在隔离样本实现既有人物的单一承嗣：保留生父母和出生位置，增加嗣子位置，由嗣子位置承接后代；用户对本次体验反馈“应该符合预期了”。具体自动化和人工验证范围见[接力](HANDOFF.md)。
- [承嗣存储](../PuJiang.V1.Persistence/IsolatedSuccessionStore.cs)负责创建、读取和修改嗣母；[工作台](../ZupuPaiBan/Views/V1FirstRootWindow.cs)提供“挂接为嗣子”和位置显示。[分支存储](../PuJiang.V1.Persistence/IsolatedBranchStore.cs)对承嗣位置拆支及被嗣母引用的配偶删除设置保护，不能据此认为复杂位置的更正、解除或删除已经实现。
- 领域契约 §7.1、§7.3、§8.4 约束唯一有效后代承接及生父处引用；§7.4、§8.5 规定祧继不自动迁移原后代承接；§13 规定删除边界。D-040 准备文档还列明解除承接不自动把后代迁回其他位置。这些是协调后续操作的边界，不等于已确定所有误录处理细节。
- 阶段计划 P2-3 清单属于既有工作台的有序项目，V1 目前按已确认的独立切片推进；旧表中“图表排序”等术语和状态不能直接当作 V1 Lineage 模型或当前实现的权威。

## 建议

建议下一步先**准备单一承嗣误录的更正或解除**：D-040 已能建立承嗣，而当前复杂位置的拆支等操作受保护，误选嗣父后的业务处理值得先明确。该建议仅为准备顺序，并未决定后代去向、历史保存方式或任何新命令。祧继仍是独立候选；如果希望先确认已有成果的持久性，也可单独做跨应用重开验证。

以上均为未来验收目标，尚未执行；选择候选、明确规则并获得实施批准后才进入对应开发。
