# V1 空节点与跨代连线契约冲突审查

> 历史审查快照：当时未修改四份 V1 契约、业务代码、测试或数据库。后续用户已明确姓名必填与连接性空节点，冲突已按 [D-034](DECISIONS.md#d-034--真实人物姓名与跨代直接连线) 协调；下文当时的待确认问题不再有效。当前切片建议见[准备文档](V1_CROSS_GENERATION_SLICE_PREPARATION.md)，长期不做旧数据兼容见 [D-033](DECISIONS.md#d-033--新项目无需旧数据兼容)。

## 用户当前意图和长期边界

- 用户澄清：所说“空节点”原意是**没有真实人物、仅起连接作用**的节点，用于可能的跨代承嗣/承祧；如果可直接跨代连线，就不需要该空节点。
- 用户明确谱匠是全新项目，在**项目完成之前**均不需要为旧数据或旧模型建立兼容、迁移或转换方案；不建立长期双套业务事实。此边界不等于删除现有工作区、隔离样本或既有测试，也不排除复用已验收 UI、代码和布局算法。实际产品数据使用及其安全要求仍按对应决策和用户当时授权处理。
- 本轮为审查，不因上述方向自动批准更改代码、数据库或四份契约；不访问任何真实数据库，不设计旧数据转换或兼容路径。

## 可复用的旧成果与 V1 缺口

- [旧布局引擎](../ZupuPaiBan/Services/HorizontalLineageLayout.cs) 支持 `allowSkippedGenerations: true`，根据传入的明确世代生成跨列正交路径；[定向测试](../PuJiang.Tests/HorizontalLineageLayoutTests.cs)覆盖显式跨代边、列位置及首子对齐。它要求子世代晚于父世代，且当前模型限定每个子节点一条父边，不能据此声称复杂多父、多位置都已支持。
- [旧工作台](../ZupuPaiBan/Views/WorkbenchProfileWindow.cs)调用该跨代布局；[内存原型](../ZupuPaiBan/Views/WorkbenchPrototypeWindow.cs)有跨代过继和出继引用虚构样例。它们是可借鉴的已实现界面/布局成果，不等于 V1 的复杂承嗣或承祧业务、持久化和完整验收已完成。
- 当前 V1 画布以 `ParentPlacementId` 递归得到父层级 + 1，并调用默认相邻世代布局；首节点虽可持久化显式世代，该世代尚未驱动画布跨代列。当前 V1 生父母、位置和投影仅覆盖普通单位置路径；复杂嗣继/祧继关系及其承接规则未接入。
- 在后续获批实施时，应从已确认的人物、关系、位置及显式世代生成投影，评估直接复用跨代布局和现有交互；缺少或冲突的数据如何提示遵守契约，不能为排版制造中间人物。这里是协调建议，非本轮实现方案或对未决业务规则的确认。

## 后续验收建议（尚未执行）

1. 使用全新隔离虚构数据，明确第 1 世与第 8 世的已确认人物及允许的关系；画布直接跨列连线，不生成中间 Person 或占位业务事实，显式世代保持不变。
2. 核对合法关系及对应 Placement 的业务语义、焦点、排行和后代承接；不得仅由画布线条推断或新增关系。嗣继与祧继各自约束及异常处理须先明确并在获批范围内验证。
3. 重新读取、切谱、自动保存及失败回滚后关系、位置和连线一致；保留既有工作台、D-030/D-031 已确认且不冲突的结果。
4. 明确区分是否允许姓名未填的真实人物与连接性图形元素；如允许真实人物，应按最终契约验收其身份、统计和编辑行为，不将其误称为连接性空节点。

## 待确认的最小问题

连接性空节点已明确不是人；在不以它补跨代连接的前提下，是否仍需要独立支持“确有其人但姓名暂未记载”的真实人物？本轮只指出该问题，不自行确定、修订契约或实施。
