# D-039 后 V1 隔离切片候选

本轮仅整理候选、前置条件和验收目标，不批准实施。继续保留现有 WPF 工作台，只用独立虚构数据，不访问真实数据库；按 D-033 项目完成前不做旧数据兼容、迁移或转换。历史行第按 D-037 暂缓，不作为本次候选。

## 当前基线

- D-038 普通拆支、分支删除及 D-039 普通独立分支挂接已完成隔离实现；用户分别反馈符合预期及“应该符合预期了”，具体以[接力](HANDOFF.md)记录为准。D-039 挂接会替换原生父，并非嗣继；跨应用重开和复杂关系不能从用户反馈推断均已验收。
- 领域契约 §7.3、§8.4 已规定嗣子关系须保留生父及原生父处人物引用，后代承接到嗣父所在位置；§7.1 要求同一人物同时最多一个有效承接位置。D-026 明确跨代时按已记录世代直接连线，不创建虚拟人物。祧子不同：领域 §7.4、§8.5 不自动迁移既有后代承接，不能混为一项。
- 当前 [V1 领域对象](../PuJiang.Domain/Entities.cs) 中有 Person、Placement、BiologicalParent 及婚配；[普通子女投影](../PuJiang.V1.Persistence/IsolatedChildStore.cs) 与[排行校验](../PuJiang.V1.Persistence/IsolatedChildOrderStore.cs) 以生父关系与父位置一致为前提，不能直接等同于支持嗣继关系、多个位置或唯一后代承接。现有跨代事实显示能力也不等于承嗣创建及完整画布行为已实现。

## 建议与前置边界

建议下一步先**准备单一承嗣关系切片**：用户此前明确提出跨代承嗣／承祧的实际需要，契约也已区分嗣继与普通迁移；选择承嗣先做契约和现状准备，可以在一个场景内核对生父引用、跨代连接和后代承接。此建议不是关系实现方案或实施授权。需要先由用户选择候选，再确认具体场景与未决规则；不因旧工作台存在过继显示或现有 V1 跨代连线而宣称 V1 承嗣已实现。

D-039 独立样本的跨应用重开及新挂接对话框覆盖仍可在用户需要时单独复验；它们是现有切片的验证，不应包装成新业务功能，也不推断用户没有体验。上述验收均为未来目标，不表示已执行。
